# De-hub `agent/agent_session_queue.py` — phases 2-5

## Problem

`agent/agent_session_queue.py` imports 66 symbols from eight sibling modules and
re-exports most of them behind `# noqa: F401`, so callers reach `steer_session`,
`_has_progress`, `determine_delivery_action`, `_transition_parent` and friends
through a module that does not own any of them. Ownership is unreadable, the
blast radius of any edit to the file spans the bridge, the worker, and every
session-lifecycle path, and tests patch hub attributes that production code never
reads.

**Current behavior:** 66 symbols are imported at the top of the hub. Callers pick
whichever path autocomplete offered them. `tests/README.md:141` still documents
the re-exports as a deliberate convenience ("kept for type checkers and editor
navigation"), which directly contradicts this issue.

**Desired outcome:** the hub imports only what its own code uses. Every other
caller names the canonical module. Ruff's own `F401` rule — already enabled —
becomes the permanent guard, because the pattern only survives today by
suppressing it.

### Correcting the issue's stated premise

Issue #2876 asserts the re-export hub "is a large part of why the file is 3,244
lines." **That is false and the plan does not inherit it.** Measured on
`origin/main`: the file is 3,235 lines and the entire import block is ~95 of
them. Deleting all 40 pure re-exports removes roughly 45 lines — about **1.4%**.

De-hubbing is worth doing for ownership clarity, honest blast radius, and killing
a class of silently-no-op test patches. It is **not** a file-size intervention,
and no phase here should be graded on line count. File length is separately
tracked by #3009.

### Finding 4 — the correct architectural guard

`F401` is already in the ruff select set (`select = ["E","F","I","N","W","UP","S110","S112"]`
in `pyproject.toml`). Ruff would flag every pure re-export today; the pattern survives
**only** because of 11 `# noqa: F401` suppressions in the hub.

Therefore the guard is a single proposition:

> `agent/agent_session_queue.py` contains no F401 suppression.

Ruff then enforces the rest natively and permanently, with no bespoke AST test to rot.
Measured today: `grep -c "F401" agent/agent_session_queue.py` → `11` (exit 0).
Control on a clean sibling: `grep -c "F401" agent/session_state.py` → `0` (exit 1).

Three traps this formulation deliberately avoids:

- **Self-match.** A repo-wide sweep for the banned string matches the guard's own source.
  Fixed structurally by scoping the read to `agent/agent_session_queue.py` alone, so the
  test file's text is never in the search space. No string-concatenation trickery.
- **Line-keyed exemptions.** None are used. Per #2805, a line-keyed allowlist silently
  un-exempts call sites on unrelated merges.
- **Over-broad module bans**, which Finding 1 shows would ban 26 legitimate imports.

### Finding 5 — the fifth detection class: untracked vault config

`~/Desktop/Valor/reflections.yaml` (and its gitignored `config/reflections.yaml` copy)
names the hub by dotted string in **three** places, invisible to `git grep` by construction:

```

L61  callable: "agent.agent_session_queue.cleanup_stale_branches_all_projects"
L71  callable: "agent.agent_session_queue.cleanup_corrupted_agent_sessions"
```

Verified: `grep -c 'agent\.agent_session_queue\.' ~/Desktop/Valor/reflections.yaml` → `3`.

`reflection_scheduler._resolve_callable` (`agent/reflection_scheduler.py:443`) `getattr`s
these off the hub. `ReflectionEntry.validate` only asserts the string is non-empty and
never resolves it; resolution failures are swallowed by a broad `except Exception` in
`run_reflection`. **A bad deletion therefore kills a daily job silently on a green-looking
worker.** This already blocked phase 1.

Note the asymmetry: `cleanup_corrupted_agent_sessions` is hub-*used* (Finding 1) so it
survives phase 5 regardless, while `cleanup_stale_branches_all_projects` is a pure
re-export and would break. Phase 2 migrates **all three** anyway, because leaving two
entries resolving through a module that does not own the symbol re-creates the exact
coupling this issue exists to remove.

## Data Flow

The one runtime path that is not a static import:

1. **Entry point:** the reflection scheduler tick reads `config/reflections.yaml`.
2. **`ReflectionEntry.validate`:** asserts `callable` is a non-empty string. Does **not**
   import or resolve it. No error surface here.
3. **`run_reflection`:** calls `_resolve_callable(entry.callable)`, which does
   `importlib.import_module(module_path)` then `getattr(module, func_name)`.
4. **Failure sink:** an `AttributeError` from step 3 is caught by a broad
   `except Exception`, recorded to `last_error`, and the scheduler keeps ticking. No
   Sentry hook, no alert, worker stays green.
5. **Output:** the daily job simply stops running, indefinitely and invisibly.

Phase 2 must therefore import-check every migration **target** before writing, exactly as
`scripts/migrate_reflections_callables.py` already does for #2875.

## Architectural Impact

- **New dependencies:** none. Every target module is already imported somewhere in the
  same process.
- **Interface changes:** none at runtime. Symbol identities are unchanged; only the
  path used to reach them changes. No signature, no behavior, no serialized format.
- **Coupling:** strictly decreasing. The hub stops being an import target for eight
  modules' worth of symbols it does not own.
- **Circular-import risk: LOW, and it improves.** Every hub import inside
  `agent/session_*.py` and `worker/__main__.py` is already **function-local** (carrying
  `# noqa: PLC0415`), precisely to dodge the existing cycle. All eight repoints in
  Finding 2 point **leaf-ward**: `agent.session_state` is a pure mutable-state leaf, and
  `session_health` / `session_completion` / `session_executor` / `session_revival` do not
  import the hub at module level. The changes reduce cycle pressure rather than adding to it.
  Two items to *verify at build time rather than assume* are listed under Risks.
- **Reversibility:** high per phase. Each phase is a self-contained revert. Phase 2 is
  additionally idempotent and has a `--check-idempotent` mode.

## Solution

### Key Elements

- **Vault callable migration (phase 2):** extend the existing tracked, idempotent
  rewrite script so `/update` repoints the three `reflections.yaml` entries onto canonical
  modules on every machine. Touches no Python module under `agent/`.
- **Production repointing (phase 3):** eight files import each symbol from its owner.
  The re-export block stays, so nothing can break.
- **Test repointing (phase 4):** ~30 test files plus the 11 patch-target strings from
  Finding 3 name the canonical module.
- **Deletion and guard (phase 5):** remove the 40 pure re-exports, drop the F401
  suppression idiom, delete the two stale summary comments, rewrite the contradicting
  paragraph in `tests/README.md`, and add the architectural test with demonstrated red.

### Flow

`origin/main` → **phase 2 merges** → `/update` runs on each machine, vault + config
rewritten → **phase 3 merges** (production names owners) → **phase 4 merges** (tests name
owners) → **phase 5 merges** (40 re-exports deleted, ruff F401 becomes the standing guard)
→ hub imports only the 26 symbols it uses.

### Technical Approach

- **Four PRs, each green on `main` standalone.** The issue sketched three phases; phase 1's
  lane sketched seven. Four is the number the evidence supports: one per irreversible
  boundary (config propagation, production, tests, deletion). Splitting further would
  create PRs with no independent verifiable outcome.
- **Phase 2 must land and propagate before phase 5.** This is real wall-clock latency
  across machines, not a merge ordering nicety. Phase 5's PR description must record the
  propagation evidence.
- **Phases 3 and 4 are independent of each other** and both independent of phase 2. Either
  can run concurrently once PR #3007 clears. Phase 5 depends on all three.
- **The 26 hub-used imports keep their current form.** Phase 5 deletes names from the
  import lists, not whole statements, wherever a statement mixes used and re-exported names.
- **Re-verify, do not trust, the phase-1 analyzer.** The issue's own comment warns that
  `scratchpad/analyze.py` had bugs in intermediate versions cutting in *both* directions
  (missed relative imports → false-dead; over-greedy alias regex → false-live). Every
  phase re-runs detection from scratch across all five classes: absolute imports, relative
  imports, aliased attribute access, patch-target strings, and the untracked vault yaml.

## Rabbit Holes

- **Shrinking the file.** Deleting all 40 pure re-exports removes ~1.4% of its length.
  Do not let any phase drift into extracting queue logic to chase a line count. #3009 owns that.
- **Promoting the function-local imports to module scope.** Once callers are repointed,
  several `# noqa: PLC0415` function-local imports *look* promotable. Resolving whether
  each is still cycle-necessary is a separate audit with its own regression surface, and
  getting it wrong takes down the bridge at import time. Leave every `PLC0415` exactly
  where it is.
- **Rewriting the 295 unaffected patch strings.** Only 11 break. Touching the other 295
  turns a reviewable diff into an unreviewable one for zero behavior change.
- **Building a general "no re-export hub anywhere" linter.** The issue asks to guard *this*
  file. A repo-wide rule needs an exemption model — `agent/__init__.py` is a legitimate
  package-level re-export — and exemption models are where line-keyed allowlists (#2805)
  come from. Scope the guard to the one file.
- **Trusting the phase-1 analyzer's output.** It is a starting point with two known
  historical bug classes, documented in the issue's own comments. Re-derive.

## Risks

### Risk 1: A deleted symbol is still named by untracked vault config
**Impact:** A daily reflection stops running on every machine that has not synced, with no
alert, no Sentry event, and a green worker. `run_reflection` swallows the `AttributeError`.
This already happened in phase 1 and was caught only because the merge gate reproduced the
`getattr` by hand.
**Mitigation:** Phase 2 ships first and must fully propagate before phase 5 merges. Phase 5's
merge gate reproduces the resolution directly for all three migrated callables rather than
inferring it from a passing suite. The vault sweep is an explicit named step in every phase's
checklist — it is invisible to static analysis by construction, so no analyzer can be trusted
to surface it.

### Risk 2: The architectural test is written to a formulation that bans legitimate imports
**Impact:** A guard phrased as "the hub must not import from `agent.session_health`" fails
against the 26 imports the hub genuinely uses (Finding 1), and the natural "fix" is an
exemption list — which is exactly the line-keyed-allowlist failure mode of #2805.
**Mitigation:** The guard asserts a single proposition — no F401 suppression in one named
file — and delegates everything else to ruff, which already has the rule enabled. Scoping
the read to one file also structurally eliminates the self-match trap. Demonstrated red is
required before merge.

### Risk 3: PR #3007 conflicts with phases 3 and 5
**Impact:** Two lanes editing a 3,235-line file concurrently produces a conflict that is
resolved by hand under time pressure — the conditions under which a re-export gets silently
restored.
**Mitigation:** Phases 3 and 5 do not start until #3007 is merged, verified via
`gh pr view 3007 --json state`. Phase 2 touches no file #3007 touches and may proceed
immediately.

### Risk 4: A repoint introduces a module-level import cycle
**Impact:** `ImportError` at process start — loud, but it would take down the bridge or worker.
**Mitigation:** Analysis says LOW (see Architectural Impact) because every repoint is
leaf-ward and the existing hub imports are already function-local. Two specific items are
**verified at build time, not assumed**: (a) `agent/__init__.py` importing
`agent.session_revival` at module level — confirm `session_revival` has no module-level
import back into the `agent` package; (b) `worker/__main__.py`'s nine-symbol repoint stays
inside the existing function-local block rather than being hoisted. Each phase's gate
includes an import smoke test over `agent`, `worker.__main__`, `tools.valor_session`,
`tools.agent_session_scheduler`, and `bridge.telegram_bridge`, which passes on `origin/main` today.

### Risk 5: A test's patch target is repointed to a module the code under test does not read
**Impact:** The patch becomes a no-op and the test passes vacuously — the #1041 failure mode,
in reverse.
**Mitigation:** Phase 4 repoints each of the 11 strings to the module whose **runtime import
site** the code under test actually reads, per the standing rule in `tests/README.md:141`.
For each of the 11, confirm the patch is observed: assert the mock was called, or verify the
test fails when the mock's behavior changes. A test that passes both with and without its
patch is not evidence.
