# PM fire-and-forget: enforce foreground-only subagents + fail-closed terminal status

## Problem

A PM (eng) session can spawn a **background** `dev` subagent, immediately emit a
user-facing `StructuredOutput {route:"user"}` ack ("I'll follow up"), and end its
turn. The turn classifies as `PM_USER` — a *clean* exit — so the session is marked
`completed` even though the subagent is still running inside the still-alive
`claude -p` process. Nothing in the system can give the PM the turn it promised;
the work completes invisibly and the human is never told. In the traced incident
(`tg_psyoptimal_-1003743854645_413`, 2026-07-26) the subagent reached `/do-merge`
on a `MERGEABLE`/`CLEAN` PR ~26s before the process died; only the
`[unmerged-branch-guard]` preserved the branch, and the PR sat open and unmerged.

**Current behavior:**
- The subagent-spawn tool (`Task`, called "the Agent tool" in prose) **defaults to
  background**. A PM that spawns `dev` without `run_in_background: false` (or with
  `true`) gets an immediate return, emits `route:"user"`, and the turn ends.
- `agent/session_runner/runner.py:1451-1455` — the `route:"user"` branch breaks the
  turn loop (`should_break=True`, `exit_reason=PM_USER`) with **zero** consultation
  of any subagent-liveness state. The completion ledger guard
  (`runner.py:1457-1492` / `completion_guard.py`) gates only `route:"complete"`.
- `agent/session_runner/router.py:311` — `PM_USER = ("pm_user", True, True, False)`
  is `is_clean=True`, so `_runner_final_status` (`agent/session_executor.py:84-96`)
  returns `"completed"`.
- On any turn unwind, `_run_one_turn`'s `finally` SIGKILLs the whole process group
  (`docs/features/headless-session-runner.md:89-119`), killing a live background
  subagent mid-flight.
- There is **no interception** of `run_in_background` on `Task`/`Agent` anywhere.
  The intended invariant — "the parent `-p` process blocks until the subagent
  finishes" (`headless-session-runner.md:15-17`) — holds **only** for foreground
  subagents. Backgrounding silently breaks it.

**Desired outcome:**
- An eng/PM session **cannot** background a subagent — enforced in code, not prose.
  With backgrounding prohibited, a subagent is always foreground, the parent turn
  blocks until it finishes, and `route:"user"` can only be emitted *after* the
  subagent completes. The fire-and-forget trace becomes impossible.
- As defense-in-depth, if a clean exit is somehow reached while a spawned subagent
  is still in flight (e.g. a future SDK change, or a slipped path), finalization is
  **fail-closed**: the session is not marked `completed`.

**Root cause pattern:** every prior fix relied on the agent *choosing* the safe behavior (prose it must follow, a primitive it must call). The reliable remedy is a **mechanical invariant** the agent cannot opt out of: prohibit backgrounding at the tool boundary, and fail closed at finalization.

## Data Flow

1. **Entry point:** PM turn runs as one `claude -p` subprocess. PM decides to delegate and calls the `Task` tool (`subagent_type: dev`).
2. **Tool boundary (NEW enforcement point):** the CLI `PreToolUse` hook (`.claude/hooks/pre_tool_use.py`) fires in the `claude -p` process. It resolves the AgentSession via the per-session sidecar (`_resolve_cli_session`), reads `tool_input.run_in_background`.
3. **Prohibition (Layer 1):** if the session is `eng` and the spawn is not explicitly foreground (`run_in_background` is `true` **or omitted** → resolves to the background default), the hook prints `HOOK BLOCK: ...` and `sys.exit(2)` — the tool call is denied and the model is told to re-issue with `run_in_background: false`.
4. **Foreground execution:** with backgrounding prohibited, the `Task` runs foreground; the parent `-p` process blocks until the subagent finishes (the documented invariant). The `result` event — and therefore any `route:"user"` classification — can only fire *after* the subagent completes.
5. **Turn end:** `runner._route_turn` classifies the turn. The post-turn sidechain scan (`sidechain_agent_ids`) already runs to capture `dev_agent_id`.
6. **Fail-closed finalization (Layer 2):** if the finalized exit is **any clean exit** (`summary.exit_reason.is_clean` — this covers all four wrap-up-eligible clean reasons: `PM_COMPLETE`, `PM_USER`, `PM_NEEDS_HUMAN`, `PM_FLOOR_DELIVERED` — not just `PM_USER`/`PM_COMPLETE`) but the newest sidechain subagent transcript shows the subagent never reached a terminal record, the runner downgrades the exit reason to a new non-clean anomaly `PM_USER_SUBAGENT_LIVE`, so `_runner_final_status` returns `"failed"` (needs-attention), not `"completed"`. **The check runs at the finalization chokepoint — AFTER the wrap-up guard (`runner.py:837-838`), not only after the route decision (`runner.py:817-819`)** — because the wrap-up guard is what assigns `PM_FLOOR_DELIVERED` (`runner.py:1558`) and can also (re)assign `PM_USER`/`PM_COMPLETE`/`PM_NEEDS_HUMAN` (`runner.py:1529/1540/1552`). A downgrade scoped to two literals placed only after line 818 would sail past a stranded subagent under `PM_NEEDS_HUMAN` or the wrap-up-guard's `PM_FLOOR_DELIVERED` — the exact "point-fix, not the invariant" hole that sank #2140.
7. **Output:** the session finalizes with a status that reflects reality; the human is not handed a false "completed".

## Solution

### Key Elements

- **Layer 1 — Enforced prohibition (PreToolUse hook):** a new check in
  `.claude/hooks/pre_tool_use.py` denies any `Task`/`Agent` spawn in an `eng`
  session that is not explicitly `run_in_background: false`. This is the
  enforced-in-code invariant that replaces the failed prose (AC5). It generalizes
  and finally *enforces* the #1915/#2051 fork prohibitions.
- **Layer 2 — Fail-closed terminal status:** a new non-clean anomaly `ExitReason`
  (`PM_USER_SUBAGENT_LIVE`) plus a runner check that downgrades **any clean exit**
  (`summary.exit_reason.is_clean` — all four wrap-up-eligible clean reasons:
  `PM_COMPLETE`, `PM_USER`, `PM_NEEDS_HUMAN`, `PM_FLOOR_DELIVERED`) to it when a
  spawned subagent is detectably still in flight at turn end. Scoping to the
  `is_clean` predicate rather than two literals — and running the check at the
  finalization chokepoint after the wrap-up guard — is what makes AC1/AC3's
  blanket claim actually hold on the bypass path. This satisfies AC3 for any
  residual/bypass path.
- **Documentation:** the remedy and its no-phantom-wait argument (AC4).

### Flow

PM turn → PM calls `Task(subagent_type: dev, run_in_background: true|omitted)` → **PreToolUse hook DENIES (exit 2)** → PM re-issues `run_in_background: false` → subagent runs foreground, parent blocks → subagent finishes → PM emits `route:"user"` → turn ends cleanly with the work actually done → session `completed` (truthfully).

Bypass path (defense-in-depth): if a background subagent somehow slips the hook → turn reaches a clean exit with the subagent still live → **Layer 2 downgrades to `PM_USER_SUBAGENT_LIVE`** → session finalizes `failed`/needs-attention, never `completed`.

### Technical Approach

- **Layer 1 hook check** (`_enforce_foreground_subagents(hook_input)` in
  `.claude/hooks/pre_tool_use.py`, called inside `main()` — NOT inside the
  module-level `except`, so `sys.exit(2)` propagates as the deny):
  - Fire only when `tool_name in ("Task", "Agent")`.
  - Resolve the session with the existing `_resolve_cli_session`. **Fail open**
    on an unresolved session or infra error (mirrors `_enforce_tool_budget`):
    a local TUI / ad-hoc `claude` process that legitimately backgrounds agents
    must not be broken. Only a positively-resolved `eng` session is gated.
  - Deny when `session.session_type == "eng"` AND `tool_input.get("run_in_background")`
    is **not exactly `False`** (i.e. `True` or omitted — omission resolves to the
    background default, per `do-sdlc/SKILL.md:26` and `test_sdlc_fork_no_background.py:259-277`).
  - Deny message: name issue #2420, instruct "re-issue with `run_in_background: false` —
    a backgrounded subagent is killed when your turn ends and its work is stranded."
  - A bug *inside* the check must fail OPEN (allow) — never block a legitimate tool
    call on an internal error. The deny is the only `sys.exit(2)`.
  - **Fail-open observability (CONCERN 2):** the fail-open branch is not silent.
    Failing open on an *unresolved* session is the exact worker condition under
    which this enforcement could vanish, so every fail-open on a `Task`/`Agent`
    spawn emits a structured log line (`[foreground-guard] fail-open:
    <reason=unresolved-session|resolution-error|internal-error>`) to stderr AND
    bumps a lightweight counter so the blind spot is observable rather than
    invisible. Reuse the hook's existing edge-log sink
    (`.claude/hooks/` writes to the per-session hook-edge dir surfaced via
    `agent/session_runner/adapter.py::_hook_edge_base_dir`); if no counter sink
    is trivially available in the hook process, at minimum the stderr log line is
    mandatory. **Follow-up observability note:** a dashboard/metric that surfaces
    the foreground-guard fail-open rate (to catch a systematic resolution
    regression that would silently disable Layer 1) is filed as a `[SEPARATE-SLUG]`
    follow-up in No-Gos — it is not built here, but the log line is the seam it
    will read.
- **Layer 2 exit-reason downgrade:**
  - Add `PM_USER_SUBAGENT_LIVE = ("pm_user_subagent_live", False, False, True)` to
    `ExitReason` in `agent/session_runner/router.py` (non-clean anomaly). The
    `ExitReason` completeness test (`tests/unit/session_runner/test_exit_reason.py`)
    forces the classification decision at add time.
  - Add a liveness helper `subagent_in_flight(cwd, claude_session_id, *, projects_root=None) -> bool`
    to `agent/session_runner/adapter.py`, next to `sidechain_agent_ids`
    (reuse the existing `sidechain_transcript_path` helper at `adapter.py:180`). It
    reads the newest `agent-*.jsonl` sidechain transcript and returns `True`
    **only** when it can positively determine the subagent has no terminal record.
    **Fail-safe:** any error, ambiguity, or missing terminal-marker knowledge
    returns `False` (do not downgrade) — a false downgrade (marking a
    genuinely-complete session `failed`) is worse than a rare miss, and Layer 1
    already prevents the trigger in normal operation.
    - **HARD GATE (blocks build-failclosed — NOT a deferrable spike):** the real
      terminal-record shape must be confirmed against an actual on-disk sidechain
      transcript **before** the helper's positive-in-flight logic is written, or
      the helper ships as an always-`False` no-op that silently negates Layer 2.
      Plan-time investigation of live transcripts under
      `~/.claude/projects/*/*/subagents/agent-*.jsonl` establishes the ground
      truth: **there is NO `result` or `Stop` record type in a sidechain JSONL.**
      Record `type` values are only `user`, `assistant`, and `attachment`. The
      terminal signal is the **last `assistant` record's `message.stop_reason`**:
      a value of `end_turn` / `stop_sequence` means the subagent completed its
      final turn (NOT in flight → `False`); a last record whose assistant
      `message.stop_reason == "tool_use"` (or a trailing `user`/tool-result record
      with no following assistant reply) means the subagent is mid-exchange
      (in flight → `True`). The helper MUST key on `message.stop_reason` of the
      newest record, **not** on a non-existent `result`/`Stop` type. If the build
      cannot reproduce this shape on a fresh transcript, it stops and reports
      rather than shipping the conservative no-op.
  - **Runner wiring — placement is load-bearing (BLOCKER fix):** wire the
    downgrade at the **finalization chokepoint**, immediately after the wrap-up
    guard block (`runner.py:837-838`) and before `publish_exit_summary`
    (`runner.py:851`) — e.g. adjacent to the `summary.user_facing_routed = ...`
    reconciliation at `runner.py:850`. Guard it on the `is_clean` predicate:
    `if summary.exit_reason.is_clean and subagent_in_flight(...): summary.exit_reason = ExitReason.PM_USER_SUBAGENT_LIVE`.
    This single chokepoint covers **all four** wrap-up-eligible clean reasons
    (`PM_COMPLETE`/`PM_USER`/`PM_NEEDS_HUMAN`/`PM_FLOOR_DELIVERED`) regardless of
    whether they were assigned by the route decision (`runner.py:818`) or the
    wrap-up guard (`runner.py:1529/1540/1552/1558`). Do **not** place it only
    after the route decision at line 818 and do **not** scope it to the two
    literals `PM_USER`/`PM_COMPLETE` — either narrowing reopens the bypass hole
    for `PM_NEEDS_HUMAN` and `PM_FLOOR_DELIVERED`. `STEER_ABORT` is also
    `is_clean=True` but `wrapup_eligible=False` and never coexists with a live
    delegated subagent; the `is_clean` scope harmlessly includes it (a live
    subagent under a steer-abort is still a real strand worth flagging). The
    override flows through `_runner_final_status` → `"failed"`.

## Rabbit Holes

- **Re-implementing a general "subagent process supervisor"** — do not build liveness polling, PID trees, or a background-agent scheduler. Layer 1 makes background subagents impossible in eng sessions; Layer 2 is a conservative sidechain check, not a supervisor.
- **Reclassifying the message mid-turn (Open Question 3 in the issue)** — prohibition makes classification-staleness moot; a conversationally-classified turn simply cannot fire-and-forget. Do not add mid-turn reclassification.
- **Touching `agent/output_router.py`** — it is the legacy path, not the runner's delivery path. Changing it would be a fix on the wrong layer (the #2140 trap).
- **Fighting the exact terminal-marker format of sidechain JSONL** — do NOT build a general JSONL state machine. But note this is *not* a deferrable time-box: the terminal-record shape is a **HARD GATE** on build-failclosed (see Technical Approach). Plan-time investigation already established the ground truth — the terminal signal is the newest record's assistant `message.stop_reason` (`end_turn`/`stop_sequence` = complete; `tool_use` / trailing tool-result = in flight); there is **no** `result`/`Stop` record type. The helper keys on that confirmed shape; it does not "stay conservative on an unconfirmed shape" (that path ships an always-`False` no-op that negates Layer 2).

## Risks

### Risk 1: Hook fails closed and breaks legitimate CLI usage
**Impact:** A local TUI or ad-hoc `claude` session that backgrounds agents gets denied.
**Mitigation:** Fail OPEN on unresolved session / infra error; only a positively-resolved `eng` AgentSession is gated. Mirrors the established `_enforce_tool_budget` contract.

### Risk 2: Foreground-only blocks a legitimately long build (looks like a hang)
**Impact:** A large `dev` build now runs synchronously inside the PM turn.
**Mitigation:** This is already the documented, intended invariant ("the parent `-p` process blocks until the subagent finishes"); the per-turn timeout (7200s for eng) and steer-preempt already bound it. No new hang class is introduced — backgrounding was never a supported parallelism mechanism (see #1915).

### Risk 3: Layer 2 false downgrade marks a good session `failed`
**Impact:** A truthfully-complete session surfaced as needs-attention.
**Mitigation:** `subagent_in_flight` is fail-safe to `False` (no downgrade) on any ambiguity; it only downgrades on a *positive* in-flight determination. Layer 1 prevents the trigger from arising in normal operation, so Layer 2 fires ~never in practice.

### Risk 4: Happy-path responsiveness regression (up to ~7200s of silence) (CONCERN 3)
**Impact:** With backgrounding prohibited, a PM that delegates a long `dev` build blocks foreground inside the turn. If the PM's only user-facing output is the terminal `route:"user"` ack emitted *after* the subagent finishes, the human can see nothing for up to the per-turn cap (7200s for eng) with no interim acknowledgement.
**Disposition (specified, not deferred):**
- **A PM *can* emit interim, non-terminal status before the blocking `Task` call — it is not structurally impossible.** The adapter's user callback (`agent/session_runner/adapter.py::_make_user_callback`, wired to `user_facing_routed`) fires whenever a `route:"user"` structured-output block is emitted *during* the turn, before the model issues the `Task` tool call. A PM that says "starting the build, will report back" and *then* calls `Task(subagent_type: dev, run_in_background: false)` delivers that ack immediately; the blocking call follows. Nothing in Layer 1 or Layer 2 prevents a pre-delegation user message — the guard only intercepts the `run_in_background` flag on the spawn itself.
- **No NEW silence class is introduced by this change.** Foreground subagents *already* blocked the turn before this plan (the documented invariant); backgrounding was never a supported responsiveness mechanism — it was the *bug* (#1915/#2051 stranded pipelines). Removing the background escape hatch does not lengthen a legitimate foreground build; it only forbids the fire-and-forget shape that produced false `completed`.
- **Sanctioned interim-ack mechanism already exists:** #2139's opt-in schedulable check-in primitive is the supported way for a long delegation to emit progress. This plan does not mandate its use (out of scope), but documents it as the responsiveness seam.
**Test:** the build adds a regression test asserting a pre-delegation `route:"user"` emission is delivered (via `user_facing_routed`) even though the subsequent foreground `Task` blocks the turn — proving interim status is reachable. See Failure Path Test Strategy.
**No AC added:** interim-ack *policy* (whether PMs are *required* to pre-ack long delegations) is a prompt/persona concern, explicitly a `[SEPARATE-SLUG]` No-Go; this bug's ACs cover only the false-`completed` invariant.

## Race Conditions

### Race 1: Sidechain scan vs. subagent completing
**Location:** `agent/session_runner/adapter.py` (`subagent_in_flight`), called at turn end in `runner.py`.
**Trigger:** The subagent writes its terminal record to `agent-*.jsonl` between the runner's post-turn scan and finalization.
**Data prerequisite:** The subagent's terminal record must be flushed to the sidechain file for the helper to read it.
**State prerequisite:** The turn's `result` event has fired (turn classified) before the scan runs.
**Mitigation:** With Layer 1, a subagent is foreground — its terminal record is written *before* the `result` event fires, so at scan time it is always present (helper returns `False`, no downgrade). The race only matters on the bypass path, where a conservative miss (no downgrade) is the fail-safe direction, and a rare false-`failed` is the tolerated worst case (Risk 3).
