## Notes on MODIFIED and REFUTED items

**Effort for do-sdlc and sdlc (rows 1-3).** Leave both at the default, or set `medium` explicitly. The binary settles the propagation question in a way that matters for other clusters: an Agent-spawned subagent takes effort from its agent definition, else from the session, and never from the skill that spawned it. A Skill-tool invocation inside a fork inherits the fork's effort unless the invoked skill declares its own. So any skill that runs nested under a lowered skill needs its own `effort:` line to be safe.

**Guard table move (row 4).** Move the table and the explanatory paragraphs to `GUARDS.md`. Keep "Known gap" and "Merge gate" in the body, since the supervisor runs them before every merge. Point the guard-parity tests at the new file with a second constant, and leave the Step 4 tests on SKILL.md.

**sdlc Hard Rules (row 8).** Remove rules 1-3. Keep 6 and 7. Decide on purpose whether plan-less issues are allowed, then either drop rules 4-5 or reconcile do-sdlc's `skipped` PLAN state with them.

**Propagation check (row 11).** Keep it. Git history shows propagation misses are the most frequent reason for plan revisions, and each revision uses up a critique cycle. Widening its scope to Data Flow, Risks, Rabbit Holes, and Verification is the evidence-backed change.

**Zero-commit checks (row 23).** Keep Step 4.5 as the early abort and Step 6.5 as the pre-push net. The redundant copy is SKILL.md step 16.

**Implementation Note template (row 17).** Add the field to the template for consistency. It is a tidy-up, and the evidence does not support calling it a finding-loss bug.

**Skeptic/Simplifier rule (row 18).** Rewrite it to name the sub-sections. A rewrite that names the whole critics changes how often findings become BLOCKERs.

**Clobber rule and "Does NOT Do" (rows 19-20).** Remove the addendum copy of the clobber rule. Replace the negatives section with one positive line in the Outcome Contract that keeps plan edits with `/do-plan`.

**test-quality.md (row 28).** Retire it, and rewrite `test_find_husk_dirs_edge_cases` in the same commit.

## Extra finding (outside the report)

`WORKFLOW.md:94-106` (Step 3.5 Post-Task Output Verification) decides that a builder "produced no changes" from `git diff --stat HEAD` plus `git status --porcelain`. Both are empty when the builder committed its work, and the skill tells builders to commit at checkpoints (`SKILL.md:162`). A builder that committed cleanly is then marked FAILED. The check should compare against the pre-task HEAD (record `git rev-parse HEAD` before dispatch, then `git diff --stat <pre>..HEAD` plus porcelain). I confirmed this from the git semantics only and did not reproduce it in a live build.
