## Notes on MODIFIED items

1. **Agent retirement needs a removal entry.** `_cleanup_stale_commands` (`scripts/update/hardlinks.py:1014-1044`) removes a `~/.claude/agents` file only when its inode matches a current source, so deleting the source orphans the copy on every machine. This is already happening: 20 agents in `~/.claude/agents/` have link count 1 (agent-architect, async-specialist, bowser, red-team, scout, and others), and they all still show up in this session's agent list. To retire the five, also (a) add `("agents", "<name>.md")` entries to `RENAMED_REMOVALS` (`hardlinks.py:79`; `_cleanup_renamed` handles the `agents` kind at line 962), (b) rerun `scripts/sync_claude_to_opencode.py` so `.opencode/agents/*.md` and `.opencode/SYNC_MANIFEST.json` drop them, and (c) update `docs/guides/valor-name-references.md:126`. `config/mcp_library.json` names the same five services but has no Python consumer and is not a dispatcher. The 20 existing orphans are a separate cleanup worth filing.

2. **Research-session continuation.** The harness recommendation should read: research sessions carry no classification, so a text-only stop ends the session with no continuation. Either add the guide's early-stop block to the research dispatch's system prompt (keyed on `extra_context.research_case_id`, as the report suggests) or route research sessions into a bounded, open-item continuation. The generic `NUDGE_MESSAGE` text ("only stop when you need human input") still reaches research sessions on the empty-output path, so wording it for unattended sessions remains worthwhile.

3. **Validator test command.** Suggested wording for lines 47/53: "Run the tests the task names with the project's test runner (in ~/src/ai, `scripts/pytest-clean.sh <paths>`); never the full suite unless the task asks."

4. **Evaluate step.** Suggested wording: start `experiment evaluate` with the Bash tool's `run_in_background`, poll `experiment show` every 60 seconds, and do not end the session or run `report` while the state is `running`. Use foreground only with an explicit 600000 ms timeout and only when the evaluation is known to finish inside it. Whether a background evaluate outlives the `claude -p` process is still open; one test run that ends a session mid-evaluate and then checks `experiment show` would settle it.
