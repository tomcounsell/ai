# Do Debrief

Resolve the scope and intended audience. Read supplied notes or collect relevant git/PR activity and declared project context. Classify material into decisions, critical heads-ups, FYIs, already-handled items, and noise. Drop the last two; do not force a brief when nothing matters to the recipient.
Aim for about 30 seconds, usually 55–80 words: lead with the decision and your recommendation, include a second material item only if needed, then batch useful FYIs. State proposed defaults as proposals, not commitments you lack authority to make. Use natural spoken language and descriptive names rather than reciting issue numbers.
Prepare a transcript and optional timestamped one-line preface. Resolve actual missing decision facts before synthesis. Use $do-voice-recording to create audio. Deliver the audio inline by default; send to a named chat only when the user has authorized that destination and action. Existing explicit authorization is sufficient. Verify delivery separately from queueing and preserve the artifact if sending fails.
