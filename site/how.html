03 · how it works

A kernel moves the work. A model does the work. A ledger keeps the record.

Send it a message in your team's chat; code turns it into a task, a model does the work, and every step lands in a record you can read.

01 · The system

Code decides what it may do; a model does the work

Every chat Valor is in has one session that speaks for it. The session answers, or starts a task.

  • The kernel, deterministic code, moves each task through its stages and decides what it may do.
  • A frontier model does the work inside each stage.

Every step is a row in a Postgres ledger, an append-only table the system cannot edit. A task's state is read from those rows, so a crash or a stop leaves nothing to reconcile.

Source: docs/architecture.md · docs/data.md

02 · Infrastructure

Machines and tech stack

Valor runs natively on macOS, on four Macs, one per client, each with its own kernel, ledger and chat bridges. The design target is a MacBook Air M4 with 16 GB of RAM, and no model runs on it.

StatePostgres 18 as a document store; no Redis
Kernelone Python 3.14 process, kept alive by launchd, the macOS service manager
AgentsClaude Code, one claude -p per turn; Pi, another agent runner, as a second harness
Meteringa gateway that prices every model call
ChannelsTelegram, Slack, email, and a local chat page
