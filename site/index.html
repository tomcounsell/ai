02 · The shape

A message becomes a task in a ledger

Each chat Valor is in has one long-lived session, and it is the one voice there. It reads the chat, answers, stays quiet, or starts a task. A task is a record in a Postgres ledger that the system cannot edit. A deterministic kernel drives the task through its stages and decides what it may do. A frontier model does the work inside each stage, one turn at a time.

Three tiers
The kernel decides what a thing may do. A cheap judgement model decides what a thing is. Frontier agents decide how to do the work, and never anything about their own authority.
Durable
A task's state is computed from its ledger rows, never stored in a field, so a crash or a stop leaves nothing to reconcile.
Bounded
Every task carries an effect ceiling. Every model call is metered. Stop is immediate and nothing durable is lost.

03 · Infrastructure

What it runs on

Valor runs Mac native. It has four Macs, one per client, and each keeps its own kernel, ledger and bridges. Only two things cross machines: the code that runs Valor and a shared memory store. The design target for one machine is a MacBook Air M4 with 16 GB of RAM, and no model runs resident on it.

PartChoice
LanguagePython 3.14, with uv and a lockfile
StatePostgres 18 as a document store: JSONB documents and an append-only events table. No Redis.
KernelOne resident process, python -m core serve, kept alive by launchd
AgentsThe claude CLI, one claude -p per turn, with Pi as a second harness
Model gatewayAn in-house proxy that meters every model call, with Anthropic and OpenAI routes
JudgementA hosted Jev-class model, with an open-weight fallback behind the same port
ChannelsTelegram, email, Slack and a local chat page, each its own process
Memorypopoto's Postgres backend, in its own schema under its own role
Scheduling and secretslaunchd, and a kernel key directory that no turn can read
