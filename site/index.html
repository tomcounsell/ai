01 · What you get

One engineer, on its own Mac, in your chats

  • Its own Mac, one per client, with its own kernel, Postgres ledger and chat bridges. Nothing is shared with another client's machine but the code that runs it.
  • One name on every channel, Valor Engels, on the team's Telegram, Slack and email.
  • From a message to a merged pull request, through a pipeline that plans, builds, tests and reviews in fresh sessions before anything merges.
  • A record you can read: the ledger holds everything it did and every model call it paid for.

Source: docs/machine.md · docs/architecture.md · docs/sdlc-state-machine.md · core/spending.py

02 · How it works

Code decides what it may do; a model does the work

Every chat Valor is in has one session that speaks for it. The session answers, or starts a task.

  • The kernel, deterministic code, moves each task through its stages and decides what it may do.
  • A frontier model does the work inside each stage.

Every step is a row in a Postgres ledger the system cannot edit. A task's state is read from those rows, so a crash or a stop leaves nothing to reconcile.

Source: docs/architecture.md · docs/data.md
