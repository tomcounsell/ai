Business and Engineering Operations at Yudame

Tom Counsell started building Valor in March 2024 to codify how a good software engineering team works. Valor is now an aligned, business-minded persona with many skills and tools for building business and software systems.

Valor is built to be aligned and corrigible: he works toward what Tom intends, and seeks correction to clarify the business goals. Neither property rests on the model's good intentions. The authority to stop, limit and correct Valor sits in code outside the model.

Architecture

How Valor works

Every chat Valor is in has one session that speaks for him. The session answers, or starts a task.

  • The kernel moves each task through its stages and decides what it may do.
  • A frontier model does the work inside each stage.

Every step is a row in a Postgres ledger the system cannot edit, and a task's state is read from those rows, so a crash or a stop leaves nothing to reconcile.

Infrastructure

Tech stack

Valor runs on machines he owns. No model runs on them; each model call goes out to the model provider.

StatePostgres 18 as a document store; no Redis
Kernelone Python 3.14 process, kept alive by launchd, the macOS service manager
AgentsClaude Code as the harness, the agent program a turn runs in: one claude -p per turn; Pi as a second harness
Meteringa gateway that prices every model call
ChannelsTelegram, Slack, email, and a local chat page
