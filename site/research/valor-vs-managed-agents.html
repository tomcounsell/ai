Valor vs Managed Agents

Written before Valor's rebuild, which cut over on 2026-10-14. The comparison describes the earlier system (Redis, Popoto, a worker and a bridge). For how Valor works now, start at the overview.

Claude Managed Agents is Anthropic's fully hosted agent harness: a pre-built loop, managed cloud containers and session persistence, all driven over an API. The study's main recommendation is to use it for execution and keep orchestration local.

Execution moves to Managed Agents and orchestration stays in Valor, with both reading the same hosted Redis.

1 · What stays local

What stays in Valor

Managed Agents is a better execution engine than a self-maintained harness: sandboxed containers, zero ops, per-millisecond billing where idle time is free, and a mature loop with caching and compaction built in. Valor is a better orchestration layer: stateful, multi-channel, and workflow-aware. Three layers of Valor stay the same whichever hosted engine runs the work:

Orchestration
The PM/Dev role split within a session, the SDLC pipeline, and the steering queue. This is the part that knows what the work is.
Integration
Telegram and email delivery, and a dozen external services routed through one identity.
Memory
Persistent, ranked, decaying recall. Valor's is in production today, while the hosted equivalent is a research preview.

The two systems meet at execution. BUILD and TEST are the clear offload candidates: the longest-running stages, the most self-contained (a plan goes in, a branch comes out), and the ones that benefit most from a clean container instead of local worktree machinery. The remaining stages stay local because they need Telegram context, git credentials, or the review gate's own inspection. The study's standing rule is that a managed agent never approves its own frontend work.

2 · Memory

Porting subconscious memory

Valor's memory recall is subconscious by design: a hook fires as the agent works, checks a bloom filter, and injects <thought> stubs into the context. The agent never decides to remember; the recall simply happens. Managed Agents has no hook equivalent: once a model turn starts generating, there is no way to insert tokens into it.

The study worked through the alternatives in order. A conscious recall tool was rejected, because an agent that has to choose to remember will forget to, and it forgets most when it is under pressure. Proxying every tool through Valor was rejected too, because then the container isn't executing anything and the agent loop has just been rebuilt inside Valor. The recommended pattern is stealth injection through workflow tools: the agent must call run_tests, git_commit, and submit_work anyway, so those are defined as custom tools that route through Valor, which executes the operation, queries memory for the current context, and returns the result plus recalled thoughts. The agent sees verbose tool output and doesn't know that some of it is memory, so recall stays subconscious. It is coarser than per-tool-call recall, but it is aimed at exactly the decision points where steering matters.

3 · Shared Redis

Sharing Redis between the two

What makes the hybrid work is a plain infrastructure step: put Redis somewhere both halves can reach. A hosted container that can reach the same Redis gets the same memory pool, the same session records, and the same conversation history as local sessions, with no code changes, because the ORM only needs a URL. Post-session extraction then writes what the hosted agent learned back into the shared pool, where every future session, local or hosted, can recall it.

This step pays off even if the hybrid never ships, because hosted Redis makes multi-machine memory sharing possible on its own. The study flags it as the quick win to take first, together with a decision to stop investing in worktree edge cases, because container isolation replaces that whole class of machinery.

4 · Recommendation

When to migrate

The study deliberately stops short of saying "migrate." Instead it sets a trigger condition: when Managed Agents ships production memory and a hook-equivalent API, Valor's subconscious memory, its main advantage, becomes fully portable, and the cost/benefit of maintaining custom execution infrastructure flips. Until both ship, the architecture stays hybrid, with orchestration local, execution hosted and Redis shared between them. The study also defined a gated experiment pipeline to run before production adoption, covering environment cold-start time, tool-call cadence per turn, whether steering messages can land mid-turn, Redis latency from inside a container, and finally a full BUILD offload judged on code quality against local baselines.

5 · What to watch

What would change the recommendation

  • A hook-equivalent API matters most, because it would make subconscious memory portable.
  • Hosted memory reaching general availability is the other half of the re-architecture trigger.
  • Mid-turn steering: whether a message sent during a running turn is injected or queued decides how fine-grained external steering can be.
  • Multi-agent sessions could eventually subsume the PM/Dev split itself.
  • Pricing on long sessions needs monitoring at scale, since hour-scale builds pay per-hour runtime rates plus tokens.
