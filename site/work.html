The work: how Valor handles chats

Valor works in the chats a team already uses. In each one, a single session speaks for it and hands the work to agents behind it.

Chats

How a chat session handles messages

The session reads the chat, memory, task status and the repository itself. Then it hands work on:

  • a quick lookup to a subagent;
  • anything on the web to the web agent;
  • anything to deliver to a task.

A task reports back to the session that started it, and only the session posts in the chat.

When Tom is still talking an idea through, the session starts nothing. It asks what only he can settle, one question per message.

Source: skills/sdlc/converse.md · tools/chat_tasks.py

Rooms

Team chats and engineering chats

Team chats

Valor waits to be mentioned, and no engineering work starts there. It can still search the web or file a GitHub issue there.

Engineering chats

Every message reaches the session, and engineering work starts here.

Each chat's purpose is written down and included in every turn's prompt.

A message Valor reads gets 👀 at once. When the turn finishes, the emoji changes to show what it did.

Source: docs/bridges/telegram.md · core/reactions.py

Attention

What reaches Tom

Every time Tom acts on a task, it is recorded as a ledger row and counted beside the money spent. This is what he receives:

  • A question, only when the answer changes the outcome.
  • A delivery, saying what was verified and what wasn't.
  • A report for each merge or send.
  • An agenda when a committed decision's watched condition has been met.

Documents come as phone-readable PDFs.

Source: docs/mission.md, The attention log · persona/delivery.md
