06 · the work

One voice in every chat.

Valor works in the chats a team already uses. In each one, a single session speaks for it and hands the work to agents behind it.

Chats

Read, then dispatch

The session reads the chat, memory, task status and the repository itself. A quick lookup goes to a subagent, anything on the web to the web agent, and anything to deliver to a task. Tasks report back to the session, never to the chat.

When Tom is still talking an idea through, the session starts nothing. It asks what only he can settle, one question per message.

Source: skills/sdlc/converse.md · tools/chat_tasks.py

Rooms

Team chats stay quiet

In a team chat Valor waits to be mentioned, and no engineering work starts there; web search and filing a GitHub issue are fine. Engineering goes to the project's engineering chat, where every message reaches the session. Each chat's purpose is written down and rides in every turn's prompt.

A message Valor reads gets 👀 at once. When the turn finishes, the emoji changes to show what it did.

Source: docs/bridges/telegram.md · core/reactions.py

Attention

What reaches Tom

Every time Tom acts on a task is a ledger row, counted beside the money. What he gets: a question, only when the answer changes the outcome; a delivery, saying what was verified and what wasn't; a report for each merge or send; and an agenda when a committed decision's watched condition has been met. Documents come as phone-readable PDFs.

Source: docs/mission.md, The attention log · persona/delivery.md
