**Cascade, 2026-09-20 (lead).** Seams v3 made the budget one integer of money. In this plan: the pre-check reserves and the close consumes `Budget(usd_micros=...)` alone, with tokens still metered in `Usage`; the gateway is the only consumer of a brief's allocation; a turn token carries a `cap` on its row and is metered against it from the gateway's own log, with no tree call. The Findings and Critique sections below are the record of earlier rounds.

## Purpose

M0 ships a "real gateway with per-Brief tokens, kill, and the tool log" and proves that "a stop leaves durable state intact and the sandbox's compute dead" (tech stack §10, PROVISIONAL, COMMITTED on scope). The gateway is the physical form of the stop button and of the legible property: every model call from every harness passes through it, so the kernel can refuse a call, cut a stream, meter tokens and money against the objective tree, and keep the one record of what the model asked for (tech stack §4, LOCKED). The first two objectives, a code change and a drafted reply, both at `propose`, each run an Executor whose every model call is metered and killable only because this component exists. The gateway kill rerun and the cache measurement in `99-integration.md` read this component's rows (tech stack §14, items 1 and 3).

Decided here: a `Gateway` class rather than module globals, because the tests build one against a fake upstream and a fake tree while production builds one from the Keychain; the seams' module-level names stay and delegate to the default instance, and the instance is the `TokenIssuer` the tree's `delegate` and `stop` accept (seams §3.2). Decided here: the tree functions are injected as an object with `remaining`, `consume`, `check_generation` coroutines (default: the `kernel.tree` module), so the gateway's tests run before the tree plan lands and the seam stays the three signatures. The default is resolved inside the factory (`import kernel.tree` in the function body, never at module load), because `kernel/tree.py` names this module as the default `TokenIssuer` (seams §3.2) and two module-level imports would be a cycle; the tree's side of that is the tree plan's. Throughout, "brief" means the string id a token was minted for: a brief id, or a turn id for the supervisor's own turns (seams v3 §3.9); the lock and the call counter key on that string either way, and the ledger calls are made for a brief id only.

### Tables

`gateway_tokens(token_sha256 text primary key, brief_id text not null, generation int not null, model_ref text not null, space_id text not null, cap_usd_micros bigint null, issued_at timestamptz not null default now())`. Insert-only. `cap_usd_micros` is set for a turn token and null for a brief token (seams v3 §3.9). Index on `(brief_id, issued_at)`, so `revoke` can find a brief's newest row by id.

`gateway_log` as seams §5.1: `id bigint identity primary key, brief_id, generation, space_id, call int, event text not null, model text, request_sha256 text, estimated_input int, usage jsonb, stop_reason text, reason text, cache_state text, schema_version int not null default 1, at timestamptz not null default now()`. Indexes: `(brief_id, call)`, `(space_id, id)`, and a partial index on `brief_id where event = 'token_revoked'`.

`request_bodies(sha256 text primary key, body jsonb not null, first_seen timestamptz not null default now())`. Inserted with `ON CONFLICT DO NOTHING`, which needs no UPDATE privilege.

Grants: `kernel_rw` INSERT and SELECT on all three; `context_ro` SELECT on `gateway_log` only, through the row-level security policy of migration 0001 (`space_id = cori_current_space()`), so a later render can total spend per space. `context_ro` has no privilege on `request_bodies` or `gateway_tokens`. All three carry the `reject_mutation()` triggers for UPDATE, DELETE, and TRUNCATE. Decided here: request bodies hold conversation text and token rows hold credential hashes, so neither is readable by the render role; the seams pattern applies RLS to tables with a `space_id`, and `gateway_tokens` gets RLS enabled with only the kernel policy.

### Tokens

`issue_token(conn, *, brief_id, generation, model_ref, space, cap=None) -> SecretStr` mints `"cori-" + secrets.token_urlsafe(32)`, inserts the `gateway_tokens` row and a `token_issued` log row on the caller's connection, and returns the plaintext. It caches nothing: the caller's transaction may still roll back, and a cached entry would authenticate a token no row backs. `brief_id` is a brief id from `tree.delegate`, or a turn id from the supervisor's turn with `cap` required (seams v3 §3.9). The plaintext is never stored; `brief.issued` carries its sha256 (seams §4). Decided here: the token encodes nothing, so a leaked prefix reveals nothing; the row carries the brief.

**Turn tokens.** A turn id has no objective, no generation, and no ledger node (seams v3 §3.9, item 2 of version 3): `check_generation` is skipped for it, revocation alone ends its calls, and its budget is the `cap` on its token row, the counted prompt plus `max_tokens` at the seat's price, set by the supervisor for the turn's one model phase. A turn token is minted with `generation = 0`, which no brief token ever carries (seams §1.4: a brief's generation is 1 plus its stops), and the gateway skips the `stale_generation` rung for a token row whose `generation` is 0. The `budget` rung for a turn compares `reserve()` against `cap_usd_micros` minus the sum of `usage.usd_micros` over the turn's earlier `response` and `cut` rows, read from the log at first presentation and kept in the per-brief call state; the closing transaction writes the row and calls no tree function. The lock and the call counter key on the id string alike.

`revoke(conn, brief_id)` reads the brief's newest `gateway_tokens` row by id to fill `generation` and `space_id`, inserts a `token_revoked` log row on the caller's connection, then adds the brief to the in-memory revoked set. A brief with no token row has nothing to revoke and `revoke` returns without a row. The stream generators check that set before every chunk, so a cut lands at the next upstream chunk (spike 03: 41 ms). If the caller's transaction later rolls back, the brief stays refused in this process until restart, which is the fail-closed direction.

At `start()` the gateway loads the revoked set from the log (`select distinct brief_id from gateway_log where event = 'token_revoked'`), which is bounded by the number of stops. A presented token is looked up in `gateway_tokens` by its hash on first presentation and the row is cached from that read only; a row is immutable so the cache is never stale, and a token whose issuing transaction rolled back is refused `unknown_token` because no row exists. Both paths fail closed.

### The call path, `POST /v1/messages`

1. Read the token from `x-api-key` or `Authorization: Bearer`. Hash it. Unknown: 401 `authentication_error`, log row `refused` with `reason = unknown_token` and `brief_id`, `generation`, `space_id` null (seams §5.1). Decided here: an unknown token is still a row, because a probe against the gateway is worth seeing.
2. Take the brief's lock. Decided here: calls are serialized per brief, so the pre-check and the consume of one call are ordered before the pre-check of the next; a PydanticAI run makes one model request at a time, so the lock costs nothing in the normal case and closes the concurrent-streams gap spike 03 left open.
3. The refusal ladder, cheapest first, each a 403 `permission_error` whose message names the reason and a `refused` row with that `reason`:
   - `revoked`: brief in the revoked set (memory).
   - `model`: `body["model"] != token.model_ref` (memory).
   - `stale_generation`: `tree.check_generation(conn, BriefToken(brief_id, token.generation))` raised. Skipped when the token row's `generation` is 0, a turn token (Tokens, lead ruling); revocation alone ends a turn's calls.
   - `budget`: `reserve(estimated_input, max_tokens, prices)`, a `Budget` in money, does not fit within `tree.remaining(conn, brief_id)`, or within the turn's cap remainder for a turn token. This is where architecture §4's conversion lives: the remaining money, at the resolved seat's prices, is the token allowance for this call. Before refusing on an estimate, re-anchor with `count_tokens` and refuse only if the exact count still does not fit. When `count_tokens` itself fails at that moment, the failure is an `upstream_error` row with `reason = count_tokens:<status or timeout>` and `call` null, the estimate becomes the whole body's canonical bytes over 3, the call is forwarded if that fallback fits, and otherwise refused with `reason = budget` and the fallback in `estimated_input`. Decided here: forwards may be estimated, refusals follow an exact count or a recorded counting failure, so a Brief is never refused by an estimate's margin while the counting endpoint answers.
4. Hash the body as received (`canonical` JSON, sorted keys, compact separators). Insert into `request_bodies`. Insert the `request` row with `call`, `estimated_input`, `request_sha256`, and `cache_state` from the prefix rule below. Commit. The request is durable before the provider is called.
5. Forward with the provider key, `anthropic-version` and `anthropic-beta` passed through, `stream: true` set upstream whatever the client asked, `cache_control` stripped when the prefix rule says so.
6. Stream. Client asked to stream: relay bytes unchanged and parse them on the side. Client asked for JSON: consume the stream, `assemble` the Message, return it as JSON. Before every chunk: if the brief is revoked, stop reading, send the SSE error event (or the 403 JSON for a non-streaming client), and close.
7. Close the call in one transaction: the `response` or `cut` row with `Usage`, `stop_reason`, `cache_state`, then, for a brief token, `tree.consume(conn, brief_id, Budget(usd_micros=cost), incurred=True)`; for a turn token, no tree call, the row is the record. `Usage` still carries every token field, since tokens are what the provider bills and what the kill rerun compares (tech stack §14). On a cut, or any end without `message_delta`: output is charged as `max_tokens` at the output price, input is what `message_start` reported or the estimate if it never arrived, and `charged_reserved = True`. The tree records the full amount, clamps remaining at zero, and appends `budget.overrun` with the shortfall when the amount exceeded what remained; it runs no generation check, so a cut call's charge lands after the stop that cut it (seams §3.2, ruling 6). The gateway keeps no clip logic of its own. The row carries `reason = overrun` when the amount exceeded the `remaining` the pre-check read. Seams §5.1 defines the mark as "when the ledger clamped"; the two definitions agree because the gateway is the only consumer of a brief's allocation (seams v3 item 1) and the per-brief lock keeps the pre-check reading current. P1's fake tree asserts the two agree one for one. The next call is refused for budget by the pre-check. Overrun is reachable only by estimate error, since `max_tokens` is reserved and refusals follow an exact count.
8. An upstream non-200 or a failure to connect, before any upstream byte, is an `upstream_error` row with `reason` the status or `connect`, the upstream body relayed to the client, nothing consumed. The gateway never retries upstream. Decided here: a retry is a spend decision the caller owns; the worker adapter runs with `max_retries=0` (05-worker), so a relayed 429 or 5xx ends the Executor run as `failed`, `brief.failed` is the supervisor's trigger, and the supervisor decides whether to delegate again.
9. Every other end closes the call the same way, whoever ended it. The stream generator's `finally` runs the close and then releases the lock: a client disconnect (Starlette cancels the generator), a `CancelledError`, or a read timeout landing after `message_start` is a `cut` row charged reserved as in step 7, because the provider billed a generation the gateway did not see finish (spike 03 surprise 2); the same landing before any upstream byte is an `upstream_error` row with `reason = timeout` or `client_disconnect` and nothing consumed. No call ends without a closing row, and no lock outlives its call.

Release the lock in every path, in the `finally`.

### The budget pre-check

`estimated_input` is exact on a brief's first call (`count_tokens` on `model`, `system`, `messages`, `tools`, `tool_choice`, `thinking`). Afterwards it is the previous call's billed input (`input + cache_creation + cache_read`) plus a delta for what was appended: the canonical bytes of the messages the previous body did not contain, divided by 3. Decided here: bytes over 3 overestimates English and JSON, and an overestimate only ever delays a call by one re-anchor. Re-anchor with `count_tokens` on every tenth call, whenever the previous body is not a prefix of the current one, and before any refusal. "Prefix" is defined: `system`, `tools`, `tool_choice`, and `thinking` equal by canonical JSON, and `prev.messages` a list prefix of `body.messages` by element equality; anything else (a changed system prompt, a compacted or edited history) re-anchors. Decided here: every tenth call, because spike 03 saw the estimate track the billed count exactly across six calls and a 410 ms cost once in ten calls is under 3% of call latency. When `count_tokens` itself fails, the failure is an `upstream_error` row (`reason = count_tokens:<status or timeout>`, `call` null), the estimate is the whole body's canonical bytes over 3, and the row's `estimated_input` carries that fallback.

`reserve()` prices `estimated_input` at the cache-write rate and `max_tokens` at the output rate, so money is reserved at the most expensive input rate a call can bill. Decided here.

`cost()` is `ceil(tokens * usd_micros_per_mtok / 1_000_000)` per usage field, summed. Prices are read from the seat file: each model entry gains `usd_per_mtok: {input, output, cache_write, cache_read}` in the YAML, which `infra/models.py` converts through `Decimal` to `usd_micros_per_mtok` integers, and the loader refuses a seated model without prices. The builder takes the four numbers per seated model from the pricing page named in tech stack's sources and records the check date in the YAML comment. Decided here: prices live beside the ids because the seat file is the one place a model is data, it is inside the trust boundary, and a price change is a reviewed edit like a model change.

### The prefix rule

The cache prefix is the provider's order: each tool, then each system block, then each message content block. `prefix_sha256(body)` hashes the canonical JSON of that sequence up to and including the first element carrying `cache_control`, with the `cache_control` keys removed; `None` when no element carries one. Per brief the gateway keeps a two-deep history of prefix hashes, and only calls that carry breakpoints enter it; a call without breakpoints neither reads nor changes it.

- No breakpoints: forward as is; `cache_state` on the `request` row is `none`; the history is untouched.
- Breakpoints, and the hash equals the previous entry, or the history holds fewer than two entries, or the previous entry equaled its own predecessor: forward as is; push the hash.
- Breakpoints, and the hash differs from the previous entry, and the previous entry differed from its own predecessor: the prefix is changing every call. Strip every `cache_control` from the forwarded body and write `cache_state = unstable` on the `request` row; push the hash. The stored body is the one received.

On the `response` row `cache_state` comes from usage: `read` when `cache_read_input_tokens > 0`, else `write` when `cache_creation_input_tokens > 0`, else `none`; `unstable` when the request was stripped. Decided here: the gateway warns rather than refuses, because tech stack §4 item 6 allows either, a refusal ends a worker's task over a cost problem, and a stripped request bills 100% where an unstable cached one bills 122% (spike 04). Decided here: one change is legitimate (the roll-up changed, the system prompt changed once; spike 04's two-tier breakpoint expects it) and two consecutive changes is the pattern the spike measured, so the rule needs two. Decided here: the gateway never injects breakpoints; the Context Builder and the worker adapter place them (tech stack §8; spike 04 `render.py`), and the gateway judges what it sees. A prefix below the model's `min_cache_prefix` caches nothing silently; the gateway records the result (`none` with breakpoints present) and the Context Builder is where the minimum is enforced.

### Serving

`serve(gateway, host="127.0.0.1", port=8788)` runs uvicorn on the app in the kernel process (tech stack §2, one process). Decided here: loopback only, because the only client is the PydanticAI loop, which runs in the kernel process (tech stack §5), and a sandbox holds no token (tech stack §2). Decided here: port 8788, because 8787 is the Cloudflare tunnel's ingress to the placeholder page (prereqs item 11), and a gateway on that port would be served at `cori.yudame.dev`. Upstream timeouts: 10 s to connect, 300 s between chunks, no total. Decided here: a 128k-token generation outlives any total timeout, and a stream silent for five minutes is dead.

### Restart

`start()` also closes every `request` row that has no `response`, `cut`, or `upstream_error` row for the same `(brief_id, call)`: it writes a `cut` row charged at the row's `estimated_input` plus the request's `max_tokens`, read from `request_bodies` through the row's `request_sha256`, with `charged_reserved = True`, and consumes it with `incurred=True`, so a brief that was stopped while the gateway was down still takes the charge. Decided here: a gateway killed mid-stream must leave a conservative ledger, the same way the broker reconciles a dangling intent (spike 02); the `call` counter continues from the log's maximum for the brief, so numbering survives a restart.

## Risks

- **One process, one memory.** The provider key sits in the same process as the kernel (tech stack §2, COMMITTED). The module boundary is a code fact; the container VM is the boundary that matters (tech stack §2 assessment).
- **Port and tunnel.** Finding 3. A later edit to `infra/tunnel` that points at 8788 would publish the gateway; the bind is loopback, which the tunnel reaches. The tunnel README should name the port as reserved for the placeholder page.

### Critique, 2026-09-20

1. **Issue-time token cache is fail-open** (Tokens, line 107; task 3, line 160). `issue_token` "caches the row in memory" on the caller's connection before that transaction commits. If `tree.delegate` rolls back, no row exists, yet the plaintext still authenticates in this process; task 3's acceptance checks the row and misses the cache. The revoke path names roll-back and chooses fail-closed (line 109); the issue path chooses the other direction. Fix: `issue_token` writes rows and caches nothing; the cache is filled only from a row read back on first presentation (line 111 already says so); task 3 gains "a token whose issuing transaction rolled back is refused `unknown_token`".
2. **A client disconnect or a mid-stream failure leaves an open call and a held lock** (call path, steps 6 to 8 and "Release the lock", lines 124 to 128). The closing transaction runs only on the three named ends. Starlette cancels the generator when the client disconnects, a `CancelledError` or an upstream read timeout can land after `message_start`, and in each case the `request` row has no closing row until the next restart and the per-brief `asyncio.Lock` is never released, so the brief's next call waits forever. The kill path is safe only because `revoke` precedes `runs.stop`'s abort. Step 8 also has a read timeout as `upstream_error` with "nothing consumed", which contradicts step 7's rule that any end without `message_delta` is charged reserved, and spike 03 surprise 2. Fix: the generator's `finally` closes the call and releases the lock: an end before any upstream byte is `upstream_error` with nothing consumed; any end after `message_start` without `message_delta` is `cut` charged reserved, whoever ended it. P1 gains a `client_disconnect` rule and task 7 a test for it.
3. **`check_generation` on a turn token is undefined** (step 3, line 120; task 6, `test_turn_token_meters_against_turn_id`). The supervisor mints turn tokens with `generation=1` for a turn id. Seams §3.2 and ruling 8 extend turn ids to `remaining`, `consume`, `release`, and `issue_token`, and say nothing for `check_generation`; the tree plan derives the fence from the objective's `brief.stopped` count, which a turn id has none of. The gateway cannot tell the two ids apart, so every supervisor turn passes through this rung, and the fake tree in tasks 6 and 9 will pass it trivially and hide the gap until integration. The seams win here: the plan states what it expects (`check_generation` passes for an id no brief carries, since a turn has no fence) as a "Decided here" with a note for the lead, and the fake tree models that behaviour, rather than the plan proposing a seam change.
