## Purpose

M0 proves "one objective end to end at `propose` inside one client space's sandbox, in code and in a drafted message; a stop leaves durable state intact and the sandbox's compute dead" (tech stack §10, milestone table). The sandbox is where both halves happen. The first objective (branch, edit, tests, commit in the client's repository at `propose`) runs its edits and tests inside a `worktree` sandbox and the Verifier re-runs the tests in a `verify` sandbox that was never the Executor's. The second objective (a drafted reply, also at `propose`) leaves its draft on a retained disk. The stop property is this component's `stop`: `container kill`, confirmed from outside the VM, with the bind-mounted disk untouched. Without this plan there is no place to run a test, no fresh VM for the Verifier, and no disk that survives a stop.

### `schemas/sandbox.py`

Fields as seams §1.9, which defines `SandboxProfileName = Literal["scratch", "verify", "worktree"]` here and has `schemas/brief.py` import it. The validator §1.9 names pins the profile table, so a wrong profile fails at construction rather than at boot: `scratch` and `verify` are `readonly=True` with an empty `env`; `worktree` is `readonly=False`; `network` is `"hostonly"` for all three, and `"none"` is refused with a message naming the day it is admitted (a runtime with a no-network mode), per the architect's ruling in seams §1.9; `mount_target` is `/work`; `mount_source` is absolute. The Literal keeps `"none"` as the seams have it. The profile is the capability, and a capability that can be built wrong is a hole.

`env` maps an environment variable name to a Keychain item name (`Secret.name` to `Secret.keychain_name`), never to a value (seams §1.9). The adapter reads the values at `create()` and they never enter a `Brief`, an event, or a table.

### `adapters/apple_container.py`

```python
class AppleContainer:
    def __init__(self, *, network: str = "cori-hostonly", sandbox_root: Path | None = None,
                 read_secret=infra.secrets.read_secret) -> None: ...
    async def create(self, profile: SandboxProfile) -> SandboxHandle: ...
    async def exec(self, h: SandboxHandle, cmd: str, *, timeout: float) -> ExecResult: ...
    async def read(self, h: SandboxHandle, path: str) -> bytes: ...
    async def write(self, h: SandboxHandle, path: str, data: bytes) -> None: ...
    async def snapshot(self, h: SandboxHandle, *, snapshot_id: SnapshotId) -> SnapshotRef: ...
    async def stop(self, h: SandboxHandle) -> StopReceipt: ...
    async def destroy(self, h: SandboxHandle) -> None: ...
    def host_path(self, h: SandboxHandle, path: str) -> Path | None: ...   # None when outside the mount
    async def running(self) -> list[SandboxHandle]: ...                     # cori-* containers with their labels
    @staticmethod
    def gateway_ip(network: str = "cori-hostonly") -> str: ...             # from `container network inspect`

class SandboxError(RuntimeError): ...
class StopUnconfirmed(SandboxError): ...
```

Every CLI call goes through `infra.sandbox.proc.run`, built on `asyncio.create_subprocess_exec`, so the adapter never blocks the kernel's event loop and every call is timed. The same runner serves `images.py` and `mounts.py`, which run in the kernel process beside the gateway's uvicorn (tech stack §2) and must not stall it.

**Names and labels.** Decided here: the container name is `cori-<profile>-<key>-<hex6>`, with `key` from the profile (objective id for `worktree`, brief id otherwise) and six random hex characters, because a worktree gets a fresh container for every generation while the mount stays. Labels set at `run`: `cori.space`, `cori.profile`, `cori.key`, `cori.mount_source`, `cori.mount_target`, `cori.readonly`, `cori.image`, which is every `SandboxProfile` field except `env`, so `running()` can rebuild a profile through the validator.

**`create(profile)`.**

1. Validate the profile (the validator above). Decided here: refuse a profile whose `mount_source` is outside `sandbox_root` unless the profile is `scratch`, whose source is a root itself.
2. For `worktree`, resolve `env`: each Keychain item is read with `read_secret`; the values plus `CORI_DATA_CLASS_<NAME>=<class>` go into a temporary file with mode 0600 passed as `--env-file`, unlinked when `run` returns. Decided here: the class label rides as a companion variable, because "class-labeled values in the process environment" (tech stack §6) has no other representation in an environment.
3. `container run -d --name <n> --network cori-hostonly --label ... --mount type=bind,source=<mount_source>,target=/work[,readonly] <image>`. Every profile boots on `cori-hostonly` (architect, seams §1.9); the default network is NAT and is never used. Nothing more is done about the network at M0: no link-down, no probe, no packet filter. What a sandbox can reach is whatever the Mac exposes on the bridge interface. This system exposes nothing there: the gateway binds `127.0.0.1:8788` (seams §3.9), Postgres and Redis accept loopback only (seams §2.2), and a sandbox holds no token in any case (tech stack §2).
4. Poll `container exec <n> true` every 100 ms until it exits 0, 30 s cap (spike 06).
5. Return `SandboxHandle(id=<n>, profile=profile, created_at=now)`.

**`exec(h, cmd, *, timeout)`.** `container exec --cwd /work <n> timeout -s KILL <ceil(timeout)> sh -c <cmd>`, with a host-side subprocess timeout of `timeout + 10` s as the backstop. Decided here: the timeout is enforced inside the VM by coreutils `timeout`, because a host-side timeout alone leaves the command running in the sandbox after the tool returns. `timed_out=True` when the exit status is 137 and `duration_ms` is at or past the requested timeout; a 137 that arrives early (the OOM killer, a `kill -9` from the script itself) keeps `exit_status=137` with `timed_out=False`. A host-side timeout kills the CLI process and returns `exit_status=-1, timed_out=True`. `duration_ms` is measured on the host. stdout and stderr are decoded as UTF-8 with replacement.

**Host-side paths.** `host_path(h, path)` normalizes `path`, requires it to be under `mount_target`, maps it onto `mount_source`, resolves symlinks with `Path.resolve()`, and requires the result to stay under `mount_source.resolve()`; otherwise it returns `None`. Decided here: the containment check runs on the resolved path, because a symlink the sandbox creates inside the mount can point at any host path, and a host-side read that followed it would hand the model a file from outside the sandbox. This is the one place the adapter can reach past the VM, so it is tested as a property (see Properties).

**`read(h, path)`.** Under the mount: read the host file. Outside the mount: `container exec <n> cat <path>` with bytes captured. A path that escapes the mount by symlink raises `PermissionError`.

**`write(h, path, data)`.** Refused with `PermissionError` when the profile is read-only (the host side of a read-only bind is writable, so the adapter enforces what the mount flag enforces inside) and when the path is outside the mount. Decided here: a write outside the mount is refused rather than bridged through `exec -i`, because every artifact has to be hashable on the host side and a file outside the mount has no durable home; the model can still write `/tmp` through `bash`. Writes are atomic (temporary file in the same directory, then rename) and create parent directories.

The tool bridge in the worker plan hashes an artifact by calling `read()` and hashing the bytes it gets, which is a host-side hash with no exec (spike 08 surprise 2). Nothing in this adapter ever runs `sha256sum` inside a container.

**`snapshot(h, *, snapshot_id)`.** A gzip tar of `mount_source` taken on the host, symlinks kept as links and never followed, written to `<sandbox_root>/<space>/snapshots/<snapshot_id>.tar.gz`; `files` holds the sha256 of every regular file by relative path, hashed on the host; `sha256` is the archive's; `id` is the `snapshot_id` the kernel minted (seams §0, §2.2, §3.5) and the adapter mints nothing. The kernel calls it after `stop` and `confirm_stop` (seams §3.5), so the archive is of a quiet disk; the disk survives a stop (spike 07, 40 of 40). Decided here: a `snapshot` on a handle whose container `inspect` still reports `running` raises `SandboxError`, because an archive of a disk something is writing is not a record of anything.

**`stop(h)`.** The spike 07 requirement.

1. `killed_at = now`; `container kill <n>` (SIGKILL by default). A nonzero exit is a runtime error, not a live sandbox: read the state and retry the kill once if it still says running (spike 07 surprise 3).
2. Probe from outside the VM every 50 ms: `container inspect <n>` must report a status other than `running`, and `container exec <n> true` must fail. Only when both hold is `confirmed_dead_at = now`, with `probe = "inspect:<status>;exec:refused"`.
3. If the probe has not confirmed within 10 s, kill again and wait another 10 s; then raise `StopUnconfirmed`. The kernel issues no replacement generation on that exception (tech stack §4).
4. A `stop` on a container that is already stopped returns a receipt whose probe confirms at once.

The receipt's `confirmed_dead_at` comes from the probe and never from the kill command's return, which spike 07 saw lag execution death by 1.4 s at the median and 21 s once.

**`destroy(h)`.** Stop if running, then `container rm -f <n>`. For `verify`, remove `mount_source` (the extracted artifact directory), and only if it lies under `<sandbox_root>/<space>/verify/`. `scratch` binds a root itself, so `destroy` removes nothing for it, and a `worktree` mount outlives its containers (seams §2.2). The kernel calls `destroy` for scratch and verify at terminal (seams §3.5); a stopped worktree container stays registered until the kernel destroys it, and `running()` never lists it.

**`running()`.** `container ls --format json` filtered to names starting with `cori-` and status `running`, each returned as a `SandboxHandle` whose profile is rebuilt from the seven labels with `env={}` and passed through the validator, and whose `created_at` is the runtime's start time. Decided here: a handle from `running()` serves `stop` and `destroy` only, because `env` is unrecoverable from the runtime and nothing else needs it after a crash. The kernel needs the list at start, because a process crash is not a stop and a sandbox that outlives the kernel process keeps its compute alive; which of them to stop is the kernel's decision, and this plan only lists them.

**`gateway_ip(network)`.** The vmnet gateway address from `container network inspect`, the one host address a sandbox can reach. Nothing of this system listens there at M0: the gateway is on loopback (seams §3.9). It serves the probe server task 7's tests bind to prove the network's shape, and the allowlisting proxy of tech stack §6 when that TODO is triggered. Spike 06 surprise 2 applies to whoever binds there: the bridge exists only while a container is attached, so the test server binds after the first boot and tolerates one retry.

### `infra/sandbox/images.py`

The kernel-built image of tech stack §6 and architecture §5.

- `lock_digest(root: Path) -> str | None`: the first twelve hex characters of sha256 over `pyproject.toml` and `uv.lock`, or `None` when the root has no `uv.lock`.
- `image_for_root(root: Path) -> str`: `cori-uv:<digest>` when the root has a lockfile, else `cori-base:3.14`. Decided here: the tag is a function of the lockfile and nothing else, so a `verify` sandbox for an artifact whose lockfile is unchanged gets the Executor's image and one whose lockfile changed gets a fresh build from the new lock, which is what "dependencies from a lockfile, never from the Executor's environment" asks for.
- `build_for_root(root: Path) -> str`: a temporary build context holding only `pyproject.toml`, `uv.lock`, and a generated Dockerfile: `FROM cori-base:3.14`, `COPY --chown=agent:agent pyproject.toml uv.lock /opt/project/`, `RUN cd /opt/project && uv sync --frozen --no-install-project`, then `WORKDIR /work`. Built with `container build -t <tag>` on the host, where PyPI is the allowlisted registry at build time. Returns the tag; a no-op when the image exists.
- `build_base()`: `container build -t cori-base:3.14 -f infra/sandbox/base.Dockerfile infra/sandbox`.

`base.Dockerfile` gains `ENV UV_PROJECT_ENVIRONMENT=/opt/venv UV_PYTHON_DOWNLOADS=never UV_NO_SYNC=1`, and `/opt/venv` and `/opt/project` owned by `agent`. Decided here: the environment lives at `/opt/venv` and not in the mount, because a `.venv` inside `/work` would be shadowed by the bind mount and would land in every snapshot. Decided here: `UV_NO_SYNC=1`, so `uv run --frozen pytest` inside a sandbox runs against `/opt/venv` as built and never tries to install the project itself, because installing a project that declares a `[build-system]` fetches its build backend from the index, which the host-only network cannot reach and the image's cache does not hold. Tests import from the checkout at `/work`, which is the current directory. A project whose tests need it installed is a case for the proxy TODO, seen when it arrives.

### `infra/sandbox/mounts.py`

The host directories the profiles mount. `sandbox_root()` is `$CORI_SANDBOX_ROOT`, default `~/.cori/sandboxes`. Every function here is `async` and runs git, tar, and `container` through `proc.run`, with the copy and archive work in `asyncio.to_thread`, because `tree.delegate` calls `profile_for` under the objective's advisory lock (seams §3.2) in the process that also serves the gateway (tech stack §2). The seams keep the call inside `delegate`; the cost is stated: a first clone of a repository root and a first `uv sync` image build take minutes, and the objective's lock is held for that long. Layout per space:

```
<sandbox_root>/<space_id>/
  repos/<owner>/<name>.git/ a mirror of a URL root (bare); fetch advances every ref
  repos/<owner>/<name>/     a read-only companion checkout of the mirror's default branch, for scratch
  worktrees/<objective_id>/ the writable objective worktree, cloned from the mirror
  verify/<key>/             an extracted snapshot, read-only
  snapshots/<id>.tar.gz
```

- `resolve_root(space, root) -> Path`. `root` must be one of `space.roots`, else `ValueError`; this is the one place membership is checked. A path root (`~/...` or `/...`) is expanded and must exist. A `github.com/<owner>/<name>` root maps to the mirror `repos/<owner>/<name>.git`: when absent it is created with `git clone --mirror` over HTTPS with `github_token` from the Keychain passed the way `broker/push_branch.py` passes it, then `origin` is reset to the plain URL so no token is written to the config; when present, `git fetch origin` runs first (a mirror fetch advances every ref, including the default branch) and a fetch failure is logged and tolerated. The companion checkout `repos/<owner>/<name>/` is a `--no-hardlinks` clone of the mirror, created when absent and `git fetch && git reset --hard origin/<default>` when present, so scratch reads the fetched tip too. Decided here: a mirror rather than a working checkout, because a fetch into a working checkout advances `origin/main` and leaves local `main` where the first clone put it, and every later worktree would start there. Decided here: the clone is a `read` the kernel process performs on the host, the same reach `push_branch` already has, because a worktree of a repository needs a checkout and nothing in the documents says where one lives (Question 3).
- `choose_root(space, artifact_kind) -> str`. The default of seams §1.4: `code` takes the first root that is a repository (a URL, or a directory containing `.git`) and every other kind takes the first root that is a plain directory. Decided here: a space with exactly one root uses it for every kind, because with one repository root and a `message` contract the rule by kind yields nothing, and the one root is the only place the work can happen; the seams' rule decides every two-root case. `Contract.root` (seams §1.4) is what the person approved, and `tree.delegate` passes it as `root=` (seams §2.2, round two); `choose_root` decides only when it is `None`.
- `prepare_worktree(space, objective_id, *, artifact_kind, max_data_class, root=None) -> SandboxProfile`. Directory `worktrees/<objective_id>`, reused when it exists (per Objective, keyed by node id; a replacement Brief after a stop shares it). For a repository root: `git clone --no-hardlinks --branch <default> <mirror> <dir>`, where `<default>` is the mirror's `HEAD` (`git symbolic-ref HEAD`), then `git checkout -b cori/<objective_id>`, `origin` set to the GitHub URL, and `user.name` and `user.email` copied from the host's global git config. For a directory root: a copy of the directory without `.git`. `env` holds every manifest `Secret` whose `data_class` is at or below `max_data_class`, as names. `image` is `image_for_root(<dir>)`, built if absent. Decided here: the worktree is a clone rather than a `git worktree`, because a worktree's `.git` file points at the mirror, which is not mounted, and the first objective commits inside the sandbox. Decided here: `--no-hardlinks`, so nothing the sandbox does to an object file can touch the mirror. Decided here: commits inside a worktree carry the host's global git identity, because the system acts as the person (README) and the host is the person's machine.
- `prepare_scratch(space, brief_id, *, artifact_kind, root=None) -> SandboxProfile`. `mount_source` is the resolved root itself, read-only, no copy: the directory for a path root, the companion checkout for a URL root; `image` by the same rule.
- `prepare_verify(space, key, snapshot: SnapshotRef) -> SandboxProfile`. Extracts the archive into `verify/<key>/` with symlinks refused, checks every extracted regular file against `snapshot.files` and raises on any mismatch, then returns a read-only profile whose `image` is `image_for_root(<extracted dir>)`, built if absent. One verification calls it twice with two keys (seams §3.5, §3.6): once for the checks container `run_checks` boots and once for the Verifier's own Brief, and each call is its own extraction, its own hash check, and its own fresh container, so the Verifier's VM never saw the checks run either. `destroy` removes each extraction. The Verifier plan copies what it needs to a writable place inside the VM; this plan mounts the artifact read-only as the table says.
- `profile_for(name, space: Space, key, *, artifact_kind, max_data_class="PROJECT", snapshot=None, root=None) -> SandboxProfile` dispatches to the three (seams §2.2, round two); `space` is the manifest and the profile's `space` field is `space.id`. A `verify` call without `snapshot`, or a `worktree` or `scratch` call with one, raises `ValueError`.
- `paths_for_space(space_id) -> list[Path]` returns the space's directories so the spaces plan's `space.destroyed` can remove them (architecture §9 names sandbox snapshots among the rows that go).

### Control flow that matters

The first objective, as this component sees it (seams §3.5, §3.6). `tree.delegate` asks `profile_for("worktree", space, objective_id, artifact_kind="code", max_data_class="PROJECT")`; the clone of PsyOptimal appears on branch `cori/<objective_id>`; `runs.run_brief` calls `create` and hands the handle to the worker, whose tools call `exec`, `read`, `write` against `/work`. On terminal: `tree.land_report`, `tree.release`, `sandbox.stop` (receipt confirmed by probe), `tree.confirm_stop` (the receipt into the store), `snapshot` with the id `runs.py` minted (archive plus host-side hashes; the worker records `snapshot.taken`), and the worktree stays on disk. Then `verify.verify_objective`: `run_checks` asks `profile_for("verify", space, <checks key>, artifact_kind="code", snapshot=ref)`, gets a read-only extraction in a fresh VM from the image for the artifact's lockfile, runs `uv run --frozen pytest`, and `destroy` removes that extraction; the Verifier's Brief asks `profile_for("verify", space, brief_id, ..., snapshot=ref)` and gets a second extraction and a second fresh VM, destroyed at its terminal. A stop from the person mid-run is `runs.stop`: abort, the same `stop`, `confirm_stop`, and nothing after it; the worktree and its branch are on disk, and `delegate` refuses the node until the receipt is recorded.

## Risks

- **virtiofs ownership of host-written files.** Spike 07 showed uid 1000 writing into a host directory owned by the person's user, which suggests the mapping is permissive in the other direction too, but no spike wrote from the host and appended from inside. Task 3's `test_host_written_file_is_writable_inside` decides. If it fails, `write` goes through `exec -i cat >` and the artifact hash is taken by reading the file back from the host side, which still meets the requirement.
- **Every profile reaches the Mac's non-loopback listeners** (Finding 1, architect's ruling). Nothing of this system listens on the bridge: the gateway is on `127.0.0.1:8788` (seams §3.9), Postgres and Redis on loopback, so from inside a sandbox the gateway is unreachable at all. What a sandbox can reach is whatever else on the Mac binds all interfaces (a development server, a file share, the placeholder page's server if it ever moves off loopback). Observe and react, per the architect; the reaction, when one is needed, is the proxy TODO or a runtime with a no-network mode.
- **The client repository's tests need services.** PsyOptimal is a Django project; its test suite may want a database the sandbox does not have. That decides which first objective the integration plan picks, and it is a fact the first real build discovers.
- **The project install inside the sandbox.** `UV_NO_SYNC=1` keeps `uv run` from building the project and fetching a build backend the host-only network cannot reach; a project whose tests import the installed package rather than the checkout fails at its first test run and is a case for the proxy TODO. Task 6's fixture declares a `[build-system]` so the chosen path is exercised.
- **The objective lock during a first clone or image build.** `profile_for` is called under `single_flight("objective:<id>")` (seams §3.2) and a first mirror clone or a first `uv sync` build takes minutes; everything is async, so the gateway keeps streaming, and the objective's other callers wait. The seams place the call there, and it happens once per repository and once per lockfile digest.
- **The bridge interface exists only while a container is attached** (spike 06 surprise 2). The probe server task 7's tests bind to `gateway_ip()` fails with `EADDRNOTAVAIL` before the first boot; the tests boot first, bind second, and tolerate one retry.
- **`container inspect` status semantics.** The probe treats any status other than `running` plus a refused `exec` as dead; both are observations from outside the VM and both are later than execution death, never earlier, which is the safe side. Spike 07's request-drop measurement remains the sharper instrument and is what the acceptance test reproduces.
- **`uv sync --frozen --no-install-project` against the real lockfile.** Checked only through the API: `requires-python = ">=3.12"` and no path sources. A private index or a git dependency in the lock would need credentials at build time; the first build tells.
- **Concurrent runs on one machine.** Other sessions boot and stop containers on the same `cori-hostonly` network (spike 07 ran under that noise). Names carry a random suffix and `running()` filters by prefix, so tests tolerate strangers.

### Critique, 2026-09-20

1. **Stale worktrees from a non-bare checkout.** `resolve_root` (line 158) runs `git fetch origin` on a working checkout under `repos/<owner>/<name>`, and `prepare_worktree` (line 160) clones that checkout. A fetch advances `origin/main` and leaves the checkout's local `main` where the first clone put it, so every worktree after the first starts at the commit the checkout was created from, whatever has landed upstream since. Fix: keep the checkout bare (`git clone --bare`, or `--mirror`, at `repos/<owner>/<name>.git`) so `fetch` advances the refs the worktree clone reads, clone the worktree from it with `-b <default branch>`, and add `test_worktree_starts_at_the_fetched_tip` to task 7 (commit upstream after the first worktree, prepare a second objective, assert its HEAD is the new tip).
2. **`running()` cannot rebuild a `SandboxHandle` from three labels.** Line 98 sets labels `cori.space`, `cori.profile`, `cori.key`; line 131 and task 8 (line 183) rebuild handles from them. `SandboxHandle.profile` is a full `SandboxProfile` (seams §1.9): `mount_source`, `readonly`, `env`, and `image` are required, the pinned-table validator runs at construction, and `env` is unrecoverable from the runtime. Fix: take `mount_source`, `readonly`, and `image` from `container inspect` (or add them as labels), set `env={}` on a rebuilt handle, and state in the design that a handle from `running()` serves `stop` and `destroy` only. Task 8's acceptance should construct the handle through the validator rather than compare three fields.
3. **`prepare_worktree` has no `root` parameter.** Line 159 says an explicit `Contract.root` is checked against `Space.roots` and used, and line 163 says `profile_for` dispatches with `root`; the signature at line 160, `prepare_worktree(space, objective_id, *, artifact_kind, max_data_class)`, cannot receive it, while `prepare_scratch` (line 161) can. Fix: `prepare_worktree(space, objective_id, *, artifact_kind, max_data_class, root=None)`, the membership check in one place (`resolve_root` is the natural one), and `test_explicit_root_wins_and_must_be_in_space_roots` covering both profiles.
4. **The gateway listens on loopback, so it is unreachable from the vmnet.** Line 133 ("The gateway plan binds there"), Risk 2 (line 208, "the gateway is the listener there"), and Risk 4 (line 210) assume a gateway bound to `gateway_ip()`. Seams §3.9 and the gateway plan bind `127.0.0.1:8788` only, because the loop runs in the kernel process (tech stack §5) and a sandbox holds no token; plan findings 15 already records that nothing inside a sandbox calls the gateway. The residual reach of a sandbox at M0 is therefore whatever else the Mac exposes on the bridge interface, and none of it is this system's. Fix: keep `gateway_ip()` and say it serves the tests' probe server (task 7) and a future proxy; rewrite Risk 2 around non-loopback listeners on the Mac; drop Risk 4 or re-aim it at the test server.
5. **Blocking subprocesses inside `tree.delegate`.** `images.py` and `mounts.py` run `git clone`, `git fetch`, `tar`, `container build`, and the archive extraction, and nothing in lines 135 to 165 says whether they are async. `tree.delegate` is async and calls `profile_for` under the objective's advisory lock (seams §3.2), in the one process that also runs the gateway's uvicorn (tech stack §2; gateway plan). A synchronous clone or image build stalls every stream and every turn for its duration. Fix: declare `profile_for` and its helpers `async` over the same `create_subprocess_exec` runner `_cli` uses (or `asyncio.to_thread` for the tar and copy work), and state the expected cost: a first clone and a first `uv sync` image build take minutes.
