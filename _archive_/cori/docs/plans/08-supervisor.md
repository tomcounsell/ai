## Purpose

M0 proves one objective end to end at `propose` inside one client space's sandbox, in code and in a drafted message, with framing in the supervisor's turn (tech stack §10, PROVISIONAL, COMMITTED on scope). The supervisor is the loop that turns a person's message into a framed contract, an approved objective, and a running Executor, and then turns every verdict, question, and correction back into the next action or the next word to the person. Neither first objective can start without the framing turn and neither can end without the turn that reads the verdict. The context render inside it is the deterministic, volatility-ordered prefix that the cache measurement at M0 is taken on (tech stack §14, item 3).

## Design

### Modules

`kernel/context.py` holds projections and the render. `kernel/supervisor.py` holds the process loop, the turn, the model call, and the actions. `prompts/supervisor/standing.md` is the one paragraph on top of VOICE.md. `schemas/context.py` is the manifest. Nothing here imports `workers/` or `adapters/`; the `Worker` and `ApprovalSurface` instances arrive from `kernel/__main__.py` (integration's) through `serve`. `kernel/context.py` never imports `gateway` at module level: `render_turn` takes a `count_tokens` coroutine whose default is resolved inside the function, the way the gateway plan resolves `kernel.tree`, because `gateway/` imports `kernel.tree` and a second module-level import would be a cycle.

### Projections (`kernel/context.py`)

Everything a turn decides from is folded from the store on every turn, spike 02 style. Two folds:

- `Thread`: from the conversation's events (`conversation.opened`, `space.switched`, `message.received`, `message.sent`, `correction.recorded`, `card.issued`, `approval.minted`, `card.expired`, `turn.started`, `turn.completed`). Fields: `conversation_id`, `space`, `messages` (event id, `person` or `supervisor`, text, in event order), `corrections` (event ids), `framing_open` (the last completed turn's action was `Say` during framing and no objective has opened since), `objective_ids`, `pending_cards`, `handled` (the set of `trigger_event_id` values named by a `turn.completed`), `open_turn` (the `turn.started` with no `turn.completed`, or None).
- `SpaceView`: for the trigger's space, from `tree.project` on every objective not in a terminal state, `question.raised` without a matching `question.answered`, pending unexpired cards, and `inbound_items` headers. Read inside one transaction on a `context_ro` connection after `spaces.bind_read_token` with a token from `spaces.mint_read_token`, so a bug in this module still cannot read across spaces (tech stack §3). The one count-only line for other spaces is a single `count(*)` of pending cards outside the space, run under `kernel_rw`, rendered as a number and nothing else.

### The render (`kernel/context.py::render_turn`)

`render_turn(space, trigger, *, count_tokens=None) -> (text, ContextManifest)`. Internally it produces the system blocks, the tool definitions, and the user message; `text` is their concatenation and the manifest's `sha256` is over it.

Slices, in `SliceName` order, each a system block wrapped as `<name>\n...\n</name>`:

| Slice | Content at M0 | Cap group in `SLICE_CAPS` (architecture §1 placeholders) |
|---|---|---|
| `procedural` | the four action tools as JSON with sorted keys (they sit before `system` on the wire and are byte-stable) | `procedural`: 8k. Decided here: the tools are a fixed few hundred tokens, and a cap makes P4 total |
| `voice` | `VOICE.md` then `prompts/supervisor/standing.md` | `voice_core`: 8k shared with `operator_digest` |
| `operator_digest` | the space's corrections from `correction.recorded`, newest first, each as `wrong: ... right: ...`; `(none)` when empty | `voice_core` |
| `rollup` | every active objective in the space in id order: id, state and reason, premise, non-goals, criteria, assumptions with status, artifact kind, root, inputs, contract budget and its basis, effect ceiling, data class, deadline as a date, last report summary | `rollup`: 30k |
| `thread_summary` | `memory.latest_summary(space, conversation_id)` when one exists, else `(none)`; writing one is out of scope | `thread`: 20k shared with `recent_turns` |
| `recent_turns` | the thread's messages, corrections, cards, and replies in event order, oldest dropped past the cap; the count dropped is rendered as one line | `thread` |
| `inbox` | pending cards, open questions, inbound item headers for the space, and the count-only line for other spaces | `inbox`: 20k |
| `on_demand` | `(none)`; the read tool arrives with the operator record | `on_demand`: 40k |

`SLICE_CAPS` is one table in `kernel/context.py` mapping each cap group to its token number and its slices; the render cuts by it and P4 reads it, so the shared caps are checked as the sums they are. Decided here: the deadline renders as a date because it is a store fact that changes only with a revision, so the cache holds; the rule in seams §0 is about clock timestamps, and this is the one place a date sits in the prefix, said out loud.

Then one user message: the trigger, rendered by type (the person's text, the verdict and report summary, the worker's question, the correction) followed by the trigger's date. Decided here: the date is `trigger.occurred_at` in the machine's local zone, never the clock, so a turn rerun after midnight renders the same bytes (spike 02); one machine runs everything (tech stack §11) and `Space` carries no zone. The same rule gives the standing day: the trigger's `occurred_at` date in that zone.

Rules:

- Deterministic: same store state in, byte-identical text out. No clock reads, no dict iteration without a sort. Budget consumption is never rendered; the roll-up shows the contract's allocation only. Decided here: consumption changes on every gateway call and would rewrite the second breakpoint every turn, and the model has no decision at M0 that depends on the number.
- Event-scoped tail: the four prefix slices (`procedural`, `voice`, `operator_digest`, `rollup`) render for every model turn; the tail slices render by trigger, per the table under Turns. Decided here: this keeps the prefix through the second breakpoint identical across trigger types, which is what makes the cache pay (spike 04).
- Breakpoints: `cache_control` after `voice` and after `rollup`. The first is placed only where the prefix reaches the seat's `min_cache_prefix` (`infra/models.py`); if `voice` is short of it the breakpoint moves to after `operator_digest`, then `rollup`, and the manifest's `SliceStat.cache_breakpoint` says where it landed.
- Tokens: `SliceStat.tokens` comes from `gateway.count_tokens(model_ref, body)` (seams §3.9), one call per slice, memoized in process by `(model_ref, slice sha256)` so a stable slice is counted once. Decided here: the memo, because spike 03 priced the endpoint at 410 ms and every prefix slice repeats across turns. A slice past its cap is cut at a line boundary from its volatile end and counted again.
- `ContextManifest.corrections_rendered` lists exactly the `correction.recorded` event ids whose text is in the render. Decided here: relevance at M0 is same space, newest first, to the cap; task-class tags and the standing set need the operator record (M1).
- Space: every read of a space-partitioned table in this module goes through the bound `context_ro` transaction; `spaces.check_may_open` runs first, so a turn in `unassigned` or an unknown space is refused before any read.

### Brief slices (`kernel/context.py::render_brief_slice`)

- Executor: blocks `voice` (VOICE.md only; the adapter prepends its class paragraph), `node` (the contract fields including `root`, then the contract's `inputs`: for `message.draft`, the inbound item's headers and its body), `path` (`(root)` at M0, since depth is 1), `memory` (`memory.retrieve(SliceQuery(space, query=premise, k=5, max_data_class="PROJECT"))`), `corrections` (the space's, as in the digest). Every block `PROJECT`. The body comes from `broker.fetch_body(effects_conn, item)` on the turn's second connection, `effects_conn`, an autocommit connection the turn opens for ledger-writing reads, because `broker` functions take a connection with no open transaction (seams §3.10); the fetch happens before `render_brief_slice` is called. Decided here: the Executor holds no `connector.read` and works from the contract, because the audience of a reply is part of what was framed and the mail it answers is an input the person saw (seams §1.4).
- Scribe: the turn's blocks forked as they are, minus `procedural`: kinds `voice`, `operator_digest`, `rollup`, `thread` (the two thread slices), `inbox`, `trigger`; data class `OPERATOR` on `operator_digest`, `thread`, and on `trigger` when the trigger is `message.received` or `correction.recorded` (the person's own words, which memory ingests as OPERATOR), `PROJECT` elsewhere; `sha256` by `ContextSlice.digest`.
- Planner and Verifier raise; the Planner is M1 and the Verifier's slice is `verify.render_verifier_slice`.

### The turn's cap

A turn's own model phase is recorded, never budgeted (architecture §4; seams v3 item 2). It touches no ledger node. Its gateway token is `gateway.issue_token(conn, brief_id=turn_id, generation=0, model_ref=<frontier>, space=space, cap=turn_cap)`, where `turn_cap = Budget(usd_micros=<the counted prompt at the frontier seat's input price plus max_tokens at its output price, rounded up>)` for the one call the turn makes, plus the same again for the one retry the model call allows. Generation 0 is what no Brief token carries and what the gateway reads as "no fence" (seams §3.9), so revocation alone ends a turn's calls; the gateway meters the turn against `cap` from its own log and calls no tree function. Decided here: the cap is the counted prompt and nothing more, because a turn is bounded by the render cap and by one trigger per event and the cap exists only so the gateway has a number to refuse against; the usage rows, which name the turn id, the conversation, and the space, are the record of what a day's turns cost (tech stack §9, the cost to watch).

Nothing gates self-approval on money: at `read` and `propose` the supervisor self-approves and tells the person the figure, or asks first when it judges the person would want to be asked (Actions, `ProposeContract`); an `act` always waits on the commit card (seams v3 §1.12). A gateway refusal of a turn's call (for `budget` against the cap, or any other reason) completes the turn with no action and a kernel-written line on the surface, as under The model call; the trigger is then handled, and the person's next message is a new trigger.

### Turns (`kernel/supervisor.py`)

`serve(surface, worker, spaces, seats)` is the process loop (seams §3.3), started by `kernel/__main__.py` after it has wired the adapters:

1. **At start.** For every `turn.started` with no `turn.completed`, rerun the turn under the same turn id (below). For every `brief.issued` with no `terminal` row, `brief.failed`, or `brief.stopped`: fence it with `tree.stop(conn, objective_id, "subtree_revoked")` for a Brief with an objective and `tree.stop_brief(conn, brief_id, "subtree_revoked")` for an objective-less Scribe, hand the fenced ids to `runs.stop` after the commit, and re-delegate once, from its approved contract at the next generation, a `RUNNING` objective left with no owner, so the chaos test's objective reaches `SUCCEEDED` without resuming a run (seams Round two: a live run is stopped, never resumed; recovery of live runs is M1). Decided here: `subtree_revoked` is the nearest `StateReason` to "the process that owned this Brief is gone". Then the stop sweep of step 4.
2. **Inbound.** Reads `surface.inbound()`. An `Utterance` becomes `message.received` followed by `memory.ingest` of that event in the same transaction; a `Correction` becomes `correction.recorded`; a `Reply` goes to `approvals.mint`; a `SpaceSwitch` goes to `approvals.switch_space(conn, conversation_id, to_space)`.
3. **Poll.** Every 250 ms, reads `events` for trigger types after an in-memory cursor. The cursor is a convenience; the truth is the projection: a candidate is handled iff a `turn.completed` names it as `trigger_event_id` (seams Round two), and a candidate whose conversation has an open turn waits for it. Once a minute, before reading triggers, `tree.expire_due` and `approvals.expire_due` (seams Round two), whose fenced Briefs the stop sweep collects. Decided here: no outbox table at M0, because the loop, the gateway, and the worker share one process (tech stack §2) and `FOR UPDATE SKIP LOCKED` needs the UPDATE privilege kernel_rw does not have (Findings 1).
4. **After every turn commits, and at start.** Start `runs.run_brief(brief)` for each Brief the turn returned, tokens included, as a background task keyed by brief id (`brief.issued` is the record and never the trigger, since it carries no token). Then the stop sweep: every Brief in the loop's spaces with a `brief.stopped` and no `brief.stop_confirmed` goes to `runs.stop`, which covers the Briefs `tree.transition` returned, the ones `expire_due` and `land_report` fenced inside the tree, and a fence that committed just before a kill.

`turn(trigger) -> tuple[TurnId, list[Brief]]`, two transactions (seams Round two):

1. **First transaction.** Under `single_flight("thread:<conversation_id>")` (`hashtextextended`, seams §0; the thread lock before any objective lock): `spaces.check_may_open`; refuse if a `turn.completed` names the trigger or the conversation has an open turn; append `turn.started`; for a trigger with a model phase, render on the `context_ro` connection to count the prompt and `gateway.issue_token(turn_id, generation=0, ..., cap=turn_cap)`. Commit. The token row is now visible to the gateway's own connection, and the token lives only in the turn's memory. A rerun after a restart finds the open `turn.started` and mints a fresh token with the same cap for the same turn id.
2. **Between the transactions.** `render_turn` again on the `context_ro` connection (byte-identical by P1; the count is memoized), then the model call with no kernel_rw transaction open, so the gateway's log writes meet no lock of this turn's.
3. **Second transaction.** Insert the `context_manifests` row (`ON CONFLICT DO NOTHING` on the hash), append `turn.rendered`, run the prelude for the trigger type (table below), execute the action, append `turn.completed` with usage and the actions taken, and delegate the implicit Scribe. Commit. Every `tree.transition` in the prelude returns the Briefs it fenced; the turn hands them and the Briefs it delegated back to `serve`, which runs and stops them after the commit.

Single-flight across the split is the open `turn.started`: the poll starts no second turn on a conversation with one, and a turn whose task is still running in this process is left to finish; a turn found open at start is rerun under its id. Decided here: an in-process turn that has not completed ten minutes after its `turn.started` is cancelled and completed with `actions: []` and a kernel-written line on the surface, so a hung model call cannot hold a thread forever. Spike 02's property holds across the split: a kill before the first commit leaves no trace; a kill after it leaves an open turn that reruns byte-identically with the same cap.

### The model call

The action tools, defined once in `kernel/supervisor.py` and always all five offered so the `procedural` slice is identical every turn:

```python
class Say(Strict, frozen=True):
    text: str = Field(max_length=4000)

class ProposeContract(Strict, frozen=True):
    message: str = Field(max_length=2000)   # what to tell the person, in the supervisor's voice
    contract: Contract                      # root, inputs, budget (the estimate), and basis set here; seams §1.4
    ask_first: bool = False                 # the supervisor's judgment: issue the commit card before work starts

class AnswerQuestion(Strict, frozen=True):
    question_id: QuestionId
    text: str = Field(max_length=2000)

class RelayQuestion(Strict, frozen=True):
    question_id: QuestionId
    note: str = Field(max_length=500)       # the card's note region; the options are the kernel's

class RequestBudget(Strict, frozen=True):
    objective_id: ObjectiveId
    usd_micros: int = Field(gt=0)           # what the supervisor asks the person to add to the root
    note: str = Field(max_length=500)

SupervisorAction = Say | ProposeContract | AnswerQuestion | RelayQuestion | RequestBudget
```

`_call(rendered, token, model_ref) -> tuple[SupervisorAction | None, Usage | None, str | None]` sends `tools` (the five, `tool_choice: any`), `system` (the blocks with their `cache_control`), `messages` (the one user message), and `max_tokens: 4096` to the gateway's `POST /v1/messages` with the turn token as bearer, streaming, and parses the single `tool_use` block into the action. Decided here: the call is made with `httpx` against the gateway, the way the gateway itself speaks upstream, so no new dependency enters `kernel/` and the cached prefix is controlled to the byte; the gateway speaks one wire format (tech stack §4, COMMITTED) and the whole vendor surface is this one function. Decided here: `max_tokens` is 4,096, enough for a contract with its assumptions and small enough that the reservation stays near the counted prompt. An action that fails validation, or is not allowed for the trigger, is retried once with the error as a second user message; a second failure completes the turn with `actions: []` and a kernel-written line on the surface saying the turn produced no action. A gateway `refused` (any reason) or `upstream_error` completes the turn the same way, with the reason in `turn.completed.actions` as `{"refused": reason}` and in the line on the surface; S4 counts it.

### Actions

- `Say`: `message.sent`, `memory.ingest` of that event, then `surface.say`.
- `ProposeContract`: the kernel checks the contract: `ceilings.max_data_class == "PROJECT"`, `max_effect_class == "propose"` and `EFFECT_RANK` of it at or below the space's ceiling, deadline within 24 hours, `task_class` in `{"code.change", "message.draft"}`, `artifact_kind != "decision_brief"` (seams §1.4), `root in space.roots`, every `inputs` entry an inbound item id of this space or a path under `root`, `budget.usd_micros > VERIFY_RESERVE[artifact_kind]`, and `basis` non-empty. Decided here: `read` is refused at framing at M0 because every M0 artifact kind is written to disk and `scratch` is read-only (seams §1.9; architecture §4 puts drafts at `propose`); `act` is refused at framing at M0 because no `act` action exists before M3 and a contract that could only wait forever is a framing error. The standing prompt states the default root rule of seams §1.4 (`code` takes the first repository root, every other kind the first plain directory), the seat prices from `infra/models.yaml`, and the verification reserve per artifact kind, so the estimate is made with the numbers in front of it (architecture §2, the estimating step); the kernel checks membership; a failed check is a retry. Then `tree.open_objective(conn, space=, conversation_id=, contract=, spaces=)` (FRAMED). When `ask_first` is False: `approvals.self_approve`, `tree.approve` (which writes `APPROVED` itself), the Executor delegation (which writes `RUNNING` itself, seams §3.2), and `message.sent` with the model's message followed by a kernel-rendered block of premise, criteria, non-goals, root, inputs, budget as dollars, basis, and deadline, so the person can object with a correction (seams v3 §1.12). When `ask_first` is True: `transition(AWAITING_APPROVAL, "commit")` and `approvals.issue_card(approvals.commit_card(objective, audience))`. No cap of any kind exists on a self-approved budget (seams v3 §1.12, architect); the standing prompt says that the person sees the figure and that the ledger records the estimate against the actual, which is the pressure on the number.
- Executor delegation: `tree.delegate(conn, DelegateRequest(objective_id, "Executor", budget=Budget(usd_micros=contract.budget.usd_micros - VERIFY_RESERVE[contract.artifact_kind]), capabilities={read@read, write@propose, bash@propose, ask@read} scoped to the space, sandbox_profile="worktree", report_schema="Report", max_data_class="PROJECT", context_slice=render_brief_slice(...)), issuer=root_capabilities(space), parent_brief=None, spaces=spaces)`. Decided here: `VERIFY_RESERVE` is one table in `kernel/supervisor.py`, money per artifact kind, held back for the Verifier (architecture §4: verification is a line item of the estimate); at M0 its values are a stated guess (the Verifier seat's price times the fixture runs' token counts, recorded in the table's comment) and the ledger of verdict costs replaces them; the ruling that no ratio between kinds of work is fixed in the kernel is about the estimate the supervisor makes, and this reserve is the kernel's own cost, which the supervisor is told; the profile is always `worktree` since `read` is refused at framing; the issuer is the space's root set on the approved contract (the lead's answer to question 3). The Brief returned, token included, goes back to `serve`, which calls `runs.run_brief` after the commit. `kernel/verify.py` sizes the Verifier from `tree.remaining(objective_id)` after the Executor's release, which is the reserve plus whatever the Executor left.
- `AnswerQuestion`: `answer(brief_id, question_id, text)`.
- `RelayQuestion`: `approvals.issue_card(approvals.question_card(objective, brief, question))` with the model's note in `note`.
- `RequestBudget`: only on the `FAILED/budget_exhausted` trigger and only for that objective; the kernel builds the `budget_increase` card as the Turns table says, with the model's note in `note` and the amount in `requested`. The grant reply raises the root by exactly that amount (seams v3 item 3).

`answer(brief_id, question_id, text, *, answered_by="supervisor")`: appends `question.answered` and calls `runs.answer(brief_id, question_id, text)`; the adapter writes the tool log's answer row (seams §3.3). `frame(conversation_id, utterance) -> ObjectiveId | None`: the `message.received` model phase, returning the objective id when the action was `ProposeContract` and `None` when it asked.

### The implicit Scribe

At the boundary of every turn that had a model phase, in the second transaction, `tree.delegate(conn, DelegateRequest(objective_id=<the conversation's active objective, or None>, "Scribe", budget=scribe_budget(manifest), capabilities={read@read, memory.episodic.write@propose, memory.operator.propose@propose} scoped to the space, sandbox_profile="scratch", report_schema="ScribeReport", max_data_class="OPERATOR", context_slice=<the fork>, instruction=None), issuer=root_capabilities(space), parent_brief=turn_id, spaces=spaces)` and `scribe.fired` with `trigger: implicit`. The tree carves the Scribe's budget from the turn's objective when there is one and makes it a root of its own when there is none (seams v3 item 5). Decided here: `scribe_budget(manifest) = Budget(usd_micros=<(manifest.total_tokens + 8_192) tokens at the summarizer seat's input price plus 8_192 at its output price, rounded up>)`, kernel-set from the fork the Scribe will read and never model-chosen, because the gateway reserves the counted prompt plus `max_tokens` and a fixed number would refuse any Scribe reading a full roll-up. A `BudgetExceeded` from the tree (an objective near its root's edge) skips the Scribe, appends `scribe.fired` with `trigger: skipped` and the reason, and says so to the person in a kernel-written line; the objective's paperwork resumes when the root is raised. The Scribe's Brief is returned with the turn's and run by `serve` after the commit. The explicit trigger (a natural-language ask from the supervisor) is out of scope at M0.

### Table

`context_manifests`: `sha256 text primary key`, `space_id text not null`, `turn_id text not null`, `manifest jsonb not null`, `rendered text not null`, `at timestamptz not null default now()`. Insert-only under the 0001 pattern (grant, trigger, RLS with `cori_current_space()`, `context_ro` granted since the table carries `space_id`). Migration `0010_supervisor.py` (seams §7). The `turn.rendered` event carries the manifest and the row holds the bytes, so "why did it think that" is a lookup by hash.

### Prompt

`prompts/supervisor/standing.md`, one paragraph under CODEOWNERS: what this seat is (the loop that frames, delegates, answers, and speaks for the system as "I"), the five actions and when each is the right one, the framing rule (rewrite the premise, name assumptions with a falsification test, choose the root and name the inputs, estimate the cost in dollars from the seat prices and the verification reserve and say the basis in a sentence, decide whether the person would want to be asked before the work starts, ask the cheapest question that most reduces uncertainty, otherwise propose), and the naming rule from the README. The seat prices and the reserve are rendered into the `procedural` slice from `infra/models.yaml` and `VERIFY_RESERVE`, so the paragraph names them and never carries a number. It never names a character and never has the system name itself.
