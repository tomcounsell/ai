## Notes

**Note 1: corrected recommendation for #2684.** Keep de-slop inline-invokable (no `context: fork`). Make each caller's gate an explicit foreground dispatch: an Agent call with `run_in_background: false` whose prompt passes only the draft path, the medium, and the audience, says "you did not write this draft", and invokes `Skill('de-slop')`. The caller waits for the returned PASS/BLOCK. This is the shape of the one observed run that worked end to end (agent-a7d6dd88b23547244, spawned from inside do-presentation's fork at spawnDepth 2, returned `DE-SLOP: PASS (edited, 6 changes)` synchronously). It also works in the Codex mirror and keeps manual `/de-slop` on in-chat text working. Apply the same wording to authenticity-pass calls. Rewrite de-slop/SKILL.md:22 to state the dispatch shape rather than "subagent or forked context". The repo's `run_in_background: false` guard (test_sdlc_fork_no_background.py) covers fork skills only; do-presentation is one, so its new Agent call must carry the literal `false` or that test's no-background check should be extended to it. Caveat: `test_sdlc_fork_no_background.py:84-88` says a fork's subagent can sit at the spawn-depth limit where Agent is withheld. do-presentation invoked from the main session is at depth 1 and was observed spawning at depth 2; if do-presentation is itself launched from a deeper subagent, the dispatch may be refused, and it should then run de-slop inline and say so in its report.

**Note 2: delivery conflict.** Switching to `tools/send_message.py` is not available today: `grep -n -i voice tools/send_message.py` returns nothing, while the relay's voice-bubble branch (bridge/telegram_relay.py:654-677) is reachable only through `valor-telegram send --voice-note`. So either document `valor-telegram send --voice-note` as the sanctioned exception in both context files and in telegram/SKILL.md:21, with the `has_pm_messages()` side effect named, or add voice-note support to `send_message.py` (a code change that also records the msg_id for the summarizer bypass). The second is the cleaner end state.

**Notes 11 and 12 ordering.** Ship the comment/reply gate additions first. Only then remove the LLM-Tell Hunter and em-dash scans from the comment and reply loops.
